## 一、赛道基本设定

| 项目 | 内容 |
|---|---|
| 赛事全称 | 2026 第八届 FinTechathon 深圳国际金融科技大赛 —— 微众银行金融科技大学生挑战赛 |
| 战略指导单位 | 深圳大学、微众银行 |
| 主办单位 | 深圳大学微众银行金融科技学院 |
| 承办单位 | 艾瞰未来（北京）科技有限公司、狗熊会 |
| 技术指导单位 | 中国计算机学会数字金融分会、清华大学金融科技研究院、IEEE 计算智能学会新加坡分会、IEEE 计算智能学会深圳分会 |
| 本赛道 | 国内赛道 · 人工智能赛道（银行 AI 智能体 / AI Banking Agent） |
| 赛道邮箱 | fintechathon@g-ican.com |
| 总奖金池 | 75 万元（单赛道 25 万元） |

**赛道定位**：国内赛道聚焦「AI 代人操作银行」（安全 + 体验）。参赛团队需构建一个 AI Banking Agent 系统，
通过自然语言对话理解用户金融意图，自主规划并执行银行业务操作，并支持通过 APP、IM 等渠道与用户连接。
系统**至少覆盖下列 3 个核心场景，鼓励完整覆盖全部场景**。

**六大核心场景**

| 编号 | 场景 | 具体要求 |
|---|---|---|
| 01 | 智能转账 | 按人名、手机号或备注转账；定时转账；拆分 AA 收款 |
| 02 | 账单分析 | 消费分类统计；异常交易识别；月度 / 年度账单报告 |
| 03 | 理财操作 | 产品推荐与对比；风险评估；一键申购 / 赎回 |
| 04 | 卡片管理 | 卡申请；额度调整；交易限制 / 解锁；卡片挂失 |
| 05 | 订阅 / 代扣管理 | 自动识别订阅扣费；续费提醒；一键取消订阅 |
| 06 | 跨场景联动 | 例如：识别生日需求，锁定资金并自动完成鲜花、蛋糕等服务预订 |

**赛题解析（官网原文）**：国内赛道聚焦「AI 代人操作银行」（安全 + 体验），共同探索 AI Agent 在金融领域的下一个范式。
AI 正在从金融工具变成金融参与者——这一变革将深刻影响银行、支付、理财、保险等每一个金融子行业。

> 注意：官网**未公开** API 规范、评测数据集、模拟银行环境接口或量化技术细则。
> 「权限分级机制、幻觉防护与注入防御、意图理解与任务规划」等能力要求只体现在评分维度中，需团队自行定义并自证。

## 二、报名规则（国内赛道通用规则）

本规则适用于人工智能赛道（国内赛道）与数据分析赛道。

1. **参赛对象** —— 参赛团队全员须为全日制在校学生（包括本科生、硕士研究生及博士研究生），专业、年级不限；
   本赛道面向中国内地及港澳台地区高校在读学生，以及在华高校就读的国际学生（含留学生、交换生、借读生）。
   （在海外高校就读的学生，包括中国籍学生，应报国际赛道。）
2. **组队要求** —— 仅接受团队报名，每支参赛队伍人数 **2—5 人**，报名时须填写全部队员信息方可提交；
   允许跨年级、跨专业、跨校组队。
3. **报名与信息真实性** —— 参赛队员须保证报名信息真实、准确、有效；**每人只能参加一支队伍**（国内与国际赛道合计），重复报名无效。
4. **独立完成与诚信** —— 参赛队伍须独立完成题目，符合相关法律法规规定，不得存在任何作弊、欺诈、侵犯他人知识产权等行为。
   参赛期间若经发现或被举报并核实存在上述行为，大赛组委会有权取消参赛队伍的参赛资格和比赛成绩。
5. **知识产权** —— 参赛作品的知识产权归参赛选手所有；主办方有权将参赛作品及作品相关信息、参赛队伍信息用于宣传品、
   相关出版物、指定及授权媒体发布、官方网站浏览及下载、展览（含巡展）等。
6. **费用与决赛保障** —— 本次竞赛不收取任何报名费用；受邀参加决赛的参赛队员，决赛期间的食宿及往返交通费用由大赛组委会统一安排，
   相关政策请见后续具体通知。

## 四、评审规则（国内人工智能赛道）

国内两个赛道根据各自作品类型执行相应评审规则。人工智能赛道评分维度：

| 权重 | 维度 | 考察内容 |
|---|---|---|
| 40% | 任务完成率 | 典型金融场景任务的完成情况、多步骤任务规划合理性及工具调用正确性 |
| 30% | 安全合规性 | 对诱导转账、信息套取、越权操作和 Prompt 注入等风险的防御能力，以及敏感操作确认和风险提示 |
| 30% | 创新性及交互体验 | 场景新颖性、真实问题解决度、对话轮次效率、追问能力、错误恢复、口语化输入和超范围兜底 |

（对比：数据分析赛道为 50% 数据理解与建模分析 + 30% 应用验证与效果评估 + 20% 产品思路与创新价值。）

## 八、技术文档模板强制提纲（5 章）

1. **项目概览** —— 项目背景、目标用户与核心使用场景；作品解决的问题与主要创新点
2. **系统架构** —— 系统架构图及各模块职责；模型、工具、数据源与外部服务说明
3. **核心算法与 Agent 设计** —— 意图理解、任务规划、工具调用与状态管理；关键算法、提示词或训练/评测方法
4. **安全设计** —— 权限分级与敏感操作确认机制；Prompt 注入、越权、隐私和错误恢复防护
5. **部署与测试** —— 运行环境、部署步骤、测试用例及已知限制

## 九、安全自评报告模板提纲

1. **权限分级** —— 各类用户、操作与权限边界；敏感操作的确认、验证与撤销机制
2. **风险测试** —— 诱导转账、信息套取、越权与 Prompt 注入测试；异常输入、工具失败与错误恢复测试
3. **数据与隐私** —— 数据来源、授权、脱敏、存储与删除机制
4. **已知风险清单** —— 风险描述、影响范围、当前缓解措施与后续计划

## 十、源代码 README 模板要求章节

项目简介（赛道/队伍/项目名/一句话介绍）→ 系统架构（含架构图）→ 环境与依赖（**明令不得提交真实密钥或敏感信息**）→
安装与运行（全新环境完整步骤）→ 测试（命令、用例位置、预期结果、已知限制）→ 仓库与部署 → 安全说明（权限分级、敏感操作确认、数据处理、已知风险）。
