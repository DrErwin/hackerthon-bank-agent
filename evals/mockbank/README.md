# v0.3 模拟银行评测集

v0.5 生日银行专项见[验证证据与覆盖边界](birthday-evidence.md)、[可执行评测](test_birthday_bank_eval.py)。下文保留 v0.3 普通转账的独立范围与历史记录。

归属：Erwin。本轮只验收普通转账需要的银行行为。预约转账、冻结与分笔核销、外部生活服务不属于本票，不在通过门槛内。

规则依据：[MockBank PRD §3–7、§13.1](../../docs/prd/MockBank-PRD-2026-09-23.md)、[银行接口字段契约 B01–B09 / B14 / B23–B25](../../docs/contracts/银行接口字段-2026-09-24.md)、[确认验证字段契约](../../docs/contracts/确认验证字段-2026-09-24.md)及[公共契约](../../docs/contracts/公共契约-2026-09-23.md)。用例编号与 `test_mockbank_eval.py` 中的测试函数一一对应；失败节点给出用例编号，便于定位银行规则、接入隔离或持久化问题。

## 虚构测试数据与重置

`conftest.py` 为每个测试在 pytest 临时目录创建独立 SQLite 银行库，启动 `MockBankService` 时装载可重复的演示种子；不复用开发者的银行数据库。数据来自模拟银行已有种子：U1 的 A1 为Ⅰ类主账户，账面与可用余额均为 6,000,000 分；A5 储蓄账户为 0 分；U2 有独立的 U2A1；U1 的 A2 是备注“妈妈”的保存收款人，A7 是银行侧涉诈拦截对象。测试使用虚构会话、账号和至少 32 字节的专用测试密钥。

每个用例重新创建临时库即从种子状态重置；重启持久化用例则在同一临时库重新打开服务，确认余额、流水和操作回执不被重播种覆盖。运行记录由 pytest 生成，不把测试结果伪装成生产验收记录。

| MB-002 | B03/B04；U1 分别按姓名、手机号、卡号、备注搜索，并核验已保存 A2 的手工账号姓名；再由 U2 核验相同资料 | 候选只含 A2 且账号掩码为 `****0002`；U1 核验匹配并返回开户行；错误资料及 U2 核验均返回 `matched=false, payee=null` | 不返回完整账号，不跨用户搜索或泄露匹配状态，不编造开户行。银行规则 / 接入隔离 |

| MB-004 | B07；A1 向 A2 转 61000 元，余额为 60000 元 | 预检查拒绝 `INSUFFICIENT_FUNDS`，指出可用 6000000 分、需 6100000 分、差 100000 分 | 金额差与错误码准确，不能变成部分转账。银行规则 |
| MB-005 | B07；A1 向 A2 转 55000 元，余额足够但超过 50000 元单笔限额 | 拒绝 `LIMIT_EXCEEDED`，`scope=single`、上限 5000000 分 | 返回触发的限额与关键数字。银行规则 |

| MB-007 | B07/B09；向银行侧涉诈收款人 A7 转 500 元 | 预检查说明 `RISK_REJECTED`；提交返回明确失败，账户余额与流水不变 | 涉诈交易不得成功或写入扣款流水。银行规则 |
| MB-008 | B23–B25、确认验证字段契约；对绑定本次转账编号和版本的 `action_step_up` 挑战提交模拟验证码，再完成模拟人脸 | 仅验证码通过时不生成验证记录；错误管理身份拒绝；两因素通过后生成动作范围记录并绑定原操作编号和版本，跨用户/会话/任务/演示轮次读取拒绝 | 挑战序列化结果不含验证码；成功凭据只对应指定动作并记录两种验证方法。银行规则 / 验证记录持久化 |
| MB-009 | 网关授权边界；分别缺少转账授权判定、授权判定明确拒绝时，尝试提交 A1 向 A2 转 500 元 | 均返回 `ACCESS_DENIED`；原操作查询为 `not_found`，余额与流水不变 | 未授权调用不进入银行提交，网关不能忽略拒绝结果。接入隔离 |
| MB-010 | B09/B14；相同 U1、操作编号、账户、收款人和金额提交两次 | 两次得到同一成功结果；查询返回原回执；只扣一次 500 元 | 操作编号幂等，账户余额为 5950000 分且只有一条流出流水。银行规则 / 持久化 |
| MB-011 | B09/B14；完成 MB-010 类交易后，以同编号改成 600 元提交，并由 U2 查询原编号 | 改参返回 `OPERATION_CONFLICT`；U2 查询返回 `ACCESS_DENIED`；U1 仍能查到原回执 | 冲突不改写原操作，不泄露他人操作。接入隔离 / 持久化 |
| MB-012 | B09/B14；慢一次开关触发提交超时，随后只查询原操作编号 | 提交返回 `CALL_TIMEOUT`；首次回查得到 `processing`，最终得到原操作成功回执；仅产生一次扣款 | 超时不被说成失败或成功，不生成新编号重发，不重复扣款。持久化 / 回查 |
| MB-013 | B14；查询当前用户从未使用的随机操作编号 | 返回 `lookup=not_found, operation=null` | 未找到与明确失败区分，不编造失败回执。回查 |
| MB-014 | B09/B14；成功转账后在同一临时银行库重开模拟银行服务 | 原操作成功回执、5950000 分余额和唯一流水仍可查询 | 服务重启不丢回执或重复装载初始余额。持久化 |

## 运行

依赖 #4 已合入，所有用例调用真实的 `BankGateway` 与 SQLite `MockBankService`，不使用契约 stub：

```bash
cd backend
python -m pytest -q ../evals/mockbank/test_mockbank_eval.py
```

运行记录（2026-09-28，PR #7）：专项评测 14 条通过；与现有银行和验证测试合跑 31 条通过。GitHub `Repository checks` 同日通过；联合验收时应重新运行并以当次结果为准。

该评测只确认银行返回、余额和流水事实；不验证 Agent 自然语言理解，也不替代安全执行器对真实入口身份、确认和授权的端到端检查。
