# 普通转账评测的数据与运行前置

本文件是01票对02/03的数据需求，**不是已实现的种子或故障开关**。数据采用最小准备方案，由实际归属目录交付。本票不修改银行、策略或API。

## 1. 公共前置

每条转账场景建立独立临时应用库与银行库、有效U1会话和专用测试密钥；TF-CNF-03的“嗯／好／行”三个样本分别初始化。合并场景的连续步骤沿原任务进行，不为原退役编号重复搭建相同环境。平台引用项复用平台当前版本回归证据，缺证据仍记Blocked。默认按 [模拟银行评测说明](../mockbank/README.md) 播种；开始时记录余额、操作/交易、outflow和模型/工具调用基线。清理只针对本用例临时库。重启用例在 **同一库** 重建服务，不重置余额，不复用开发者演示库。

默认转出A1，初始余额60000元、Ⅰ类单笔/日限额50000元；A5余额0，U2A1归U2。默认收款A2备注“妈妈”、姓名王阿姨；A3备注“房东”；A7为银行涉诈对象。每条专用设置覆盖默认前置，不能拿上一条已扣余额作为下一条起点。

完整手机号、卡号及手工资料走F36专用受控输入，不送进模型；展示使用脱敏字段。缺额、选人、改额走当前任务允许的专用输入。表中“有效确认与验证”指真实后端可信记录，不是模型/前端自写approved/verified。

专用找人/手工资料用例先通过不含原始号码的转账意图建立缺收款人的待输入原任务，再在其当前交互中用F36录入。每条声明目标payer；自然语言明确默认主账户A1且账户信息核对有效时使用A1，需要多账户消歧的用例明确取消默认依据并要求用户选择。D5是所有需要进入风险检查的用例公共前置；表里未另标D5时仍须准备，除明确测试风险依赖缺失的条目。

| D4 验证 | 低风险码、中风险当前动作的码+管理员模拟人脸；可控真实时钟、专用模拟码、迟到响应和技术故障 | 模拟银行已有验证；03适配；专业规则审查归Ringo |
| D5 可信风险 | 为各用户/动作准备low/medium/high或依赖缺失事实及来源；正常、修改、各金额样本均有匹配事实，经真实安全入口裁决 | 03或安全提供方；不把500/501/502当普遍风险阈值，不全局allow，不由模型自报风险 |
| D6 银行故障 | 提交超时，原操作查询成功/失败/processing/not_found/临时故障/权限失效；真实层使用隔离模拟银行受控故障 | 慢一次已有；其他由03适配或所属目录提供；替身明确标出 |
| D7 中断点 | 创建、检查点、编号保存、提交前后、验证绑定、结果/日志保存等指定点中断，记录资金接口是否已调用 | 03注入，保留原库/记录，重建同一组合 |

冻结余额与账户frozen状态是不同事实，判定归银行。A5默认0元，多账户成功用例必须另备足够资金。边界金额同时准备合法风险事实，避免用例因无匹配风险配置而停在安全依赖缺失，误判为银行拒绝。

D4默认当前500元动作已确认但未提交资金，当前会话/确认均有效；与表中明确“尚未确认、取消、过期、新任务”的设置冲突时以该行明确阶段为准。D2的日/年已用额度须通过银行实际认可的历史转出记录准备，并固定对应银行业务日期；只改账户上的累计数字而银行仍按流水计算不算前置满足。实时有效期和请求等待继续使用真实时钟。

## 3. 执行收尾

1. 保存case数据版本、用户/会话/轮次、时钟及账本基线；前置满足才执行。
2. 每个输入/按钮后采集任务、交互、确认/验证、资金调用与账本。等待阶段检查Z，成功检查S，恢复检查O，定义见 [判定规则](README.md#3-怎样判定通过)。
3. 最后核对原operation、transaction、outflow与页面回执，当前余额不能替代原操作结果。
4. 输出ID、运行层、实际步骤、逐项断言、耗时、失败归属、脱敏证据和状态；失败也保存证据，结束恢复本用例故障开关。

完成条件：从干净前置重跑可核对；故障不污染其他用例；重启确实恢复持久化原任务。

## 4. 已知缺口

- D1/D2新联系人和账户待交付，本票只定义需求。
- AF04须同任务修改。既有浏览器“取消旧任务后另建600元”不能替代；缺公开修改路径时记Blocked并交归属目录，不改期望。
- 同句纠错、关系称呼、多轮补齐要用真实GLM证明；固定解析替身只证明流程。
- 可信风险来源、页面入口或故障注入不可用时注明提供方，不能打印预期结果充当实跑。
- 现有修改、恢复、防重复及权限测试供03参考；不重新实现业务规则，不把已有测试全部描述成单一500元桩。
