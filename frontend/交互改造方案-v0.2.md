# 前端交互改造方案 v0.2

2026-10-26。以 `origin/main@00543b4` 的前端为实现基线；初轮审查来自 `9a479ea`，已补看期间合入的生日页面 #314。

## 核心判断

目前功能已经覆盖账户、收款人、转账、账单、订阅和联动，但“聊天消息 + 多层卡片 + 重复说明”把资料和动作拆散了。应围绕一个人正在办的一件事组织界面，让他看着信息就能往下走。

## 全部前台路径的处理

| 路径 | 现状问题 | 改造方向 | 关键资料直接展示 |
|---|---|---|---|
| 首页 / 对话 | 服务入口在首条消息，会滚走；底部信息堆叠 | 常驻“办事、资料、记录”结构；对话承担问答和解释 | 可办业务、未完成事项、最近资料 |
| 账户 | 账户列表与正在办理的事项联系不强 | 在任务内打开账户选择，选完回原处 | 银行、尾号、账户用途、当前可用余额 |
| 收款人 | 查得到但独立列表启动转账不足；新增入口受任务阶段限制 | 就近搜索/选择；独立表单添加本次收款人；为常用收款人管理记录接口缺口 | 备注、掩码姓名、银行、尾号 |
| 转账填写 | 先问金额；选人选卡后摘要不足 | 选人→填金额→核对；有已知信息时跳过重复询问，摘要持续可见 | 收款人、付款卡、余额、金额 |
| 确认 / 修改 | 多个提示层重复；新旧确认不易辨认 | 一张清楚的核对单，修改入口贴近字段；旧确认折叠成记录 | 本次对象、金额、费用、时间、影响 |
| 验证 | 专用输入已有；周边说明较长 | 只展示当前验证与必要帮助；失败就地重试 | 验证对象、方式、有效状态 |
| 等待 / 结果 | 等待说明防御性强；部分结果机械截取前三项 | 显示实际阶段，持续回执按业务重要性排字段 | 对象、金额、状态、时间、下一步 |
| 账单 | 月份切换和账户条件不够就近 | 快捷月份+账户筛选；分类点开，单笔就地展开，长列表抽屉 | 统计范围、收入、支出、分类、单笔去向 |
| 自动扣费 | 可执行签约、疑似线索、退订结果理解成本高 | 按真实状态分组；每行一个主动作；停扣后保留行内结果 | 服务、金额/周期、扣费卡、状态、退款范围 |
| 养老金安排 | 多步事项容易淹没在子任务中 | 整体目标持续可见，每次只处理一项本人决定 | 本次收入、生活费、各去向与余额 |
| 减支安排 | 总建议与每项停扣之间来回跳 | 勾选要处理的项目，逐项核对，最后汇总实际结果 | 每月金额、选择项目、已完成与待处理 |
| 生日安排 | #314 已接商品/数量/配送专用输入、受控修改和结构化收尾，仍需视觉与适老化走查 | 用分步总览呈现预算、商品、配送、核对和分项结果 | 冻结、消费、释放、待处理分别清楚显示 |
| 历史 / 恢复 | 系统术语较多 | 原记录内展开；找回摘要后继续；结果未知查询原操作 | 当时资料、当前状态、可用动作 |
| 断线 / 空数据 / 失败 | 提示多，下一步不够突出 | 每种状态一个清楚行动；已填内容按数据边界保留 | 原因、已知事实、下一步 |

管理演示台用于造状态和观察证据，保持独立入口；本次视觉系统首先服务用户前台。真实语音/朗读尚待能力接入；先保证点选和打字完整可用。

## 不能只靠换组件解决的事项

1. **信息顺序**：将办理资料集中在当前任务，去掉重复摘要与重复状态。已具备的信息不再问。
2. **适合字段的输入**：金额、日期、电话、地址、商品数量分别用对应控件；不把所有问题塞进通用文字框。
3. **准确反馈**：成功、失败、待核实各自说明；交易结果留在页面。Toast 只用于普通动作的即时反馈。
4. **数据与隐私**：保留未提交草稿；敏感配送提交后只保留服务端掩码/引用。实际接口限制不能由前端假保存绕过。
5. **话术来源**：前端固定文案、业务/平台固定回复、模型回复分开处理。模型提示词已经要求简短，不能把全部问题归为提示词不足。
6. **可达性**：大字、键盘、触控、焦点、读屏、软键盘和回看位置是同一体验的一部分。

## 原型与接口差异

原型使用虚构数据，表达整套交互方向。保存常用收款人/备注、独立列表直接发起转账需补齐或接通对应流程；不得显示假保存成功。配送原型中的未提交资料可以回填，正式流程提交后遵守受控引用和掩码规则。

完整点击范围、截图和现状审查见本次交付的 `frontend-ux-prototype-20261026` 原型包。生日原型演示到预算核对；实际冻结、逐笔付款和收尾以现行服务端路径为基础继续设计。原型不是产品验收记录。

## 验收方式

按真实任务观察：找到收款人、换付款卡、填写金额、改错、核对、验证、查看结果、断线后继续。记录完成率、错点次数、返回次数、求助次数和读懂结果所需时间。先做代表性手机任务走查，再由老人实际试用；不虚构改善百分比。

技术检查覆盖有意义的变更：组件打开/关闭与焦点、服务入口可达、状态展示、字号切换，现有前端回归及构建。浏览器检查 390px、桌面和 200% 放大；实体手机、真实后端/模型、读屏与老人使用分别留证。
