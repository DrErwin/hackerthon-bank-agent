# 银行助手设计系统 v0.3 · 对话驱动

2026-10-26 · 手机优先、电脑适配。适用用户前台；管理演示台保留信息密度。取代 v0.1 中的视觉与组件选型，业务能力仍以现行接口为准。

## 体验目标

对话是主界面，业务卡片是助手提供的可操作回答。用户说出目标，助手用一句话引导当前步骤；点选与打字共同推进同一件事。资料、状态与下一步都在当前对话里。

- **随时说得上话**：输入框常驻底部；首次进入直接看见对话邀请和可点的需求示例。
- **随时找得到**：输入框上方“查资料 / 办业务”打开工具抽屉，顶部“记录”回看已办事项。“接着办”回到正在进行的任务。
- **资料跟着事情走**：转账中的收款人、付款卡、余额、金额持续可见；查询资料后回到原任务。
- **每次一个决定**：选择对象用列表，填写资料用表单，核对用清单，等待用状态，结果用回执。
- **可回看、可修改**：未提交的表单保留；修改后重新核对。配送等敏感资料提交后展示服务端掩码，引用失效时按服务端要求重填。
- **准确且亲切**：一句话说明发生什么和下一步；系统术语留在开发文档。

## 组件选型

| 用途 | 定案 | 使用方式 |
|---|---|---|
| 基础组件 | shadcn/ui，Radix 版本 | 源码纳入 `src/components/ui/`，按本系统调整字号、焦点和间距 |
| 样式 | Tailwind CSS 4 + 现有 shell CSS | 新组件使用工具类；旧页面逐步迁移；不引入全局样式重置影响历史页 |
| 图标 | Lucide React | 常规 22–24px，统一线宽；图标旁保留动作文字，装饰图标对读屏隐藏 |
| 手机抽屉 | shadcn Drawer / Vaul | 下方展开，滚动在抽屉内部，有明确关闭按钮 |
| 电脑侧栏 | shadcn Sheet / Radix Dialog | 右侧展开；关闭恢复到触发按钮；Esc 可关闭 |
| 轻提示 | Sonner | 仅用于字号、复制等普通反馈；可关闭，停留 6 秒 |
| 等待 | Progress、Skeleton、Spinner | 已知进度才显示百分比；未知进度显示循环条和实际阶段 |

参考：[shadcn Vite](https://ui.shadcn.com/docs/installation/vite)、[Drawer](https://ui.shadcn.com/docs/components/radix/drawer)、[Sheet](https://ui.shadcn.com/docs/components/radix/sheet)、[Sonner](https://ui.shadcn.com/docs/components/radix/sonner)、[Lucide](https://lucide.dev/guide/react/)。依赖版本以 lockfile 为准。

## 视觉变量

暖白底、深色文字、深橙操作色。用留白与标题分组，减少框套框和重复标签。

| 语义 | 值 | 用途 |
|---|---|---|
| 背景 | `#F5F5EF` | 页面 |
| 表面 | `#FFFFFF` | 表单、抽屉、重要摘要 |
| 主文字 | `#272A25` | 正文和金额 |
| 次文字 | `#5A6257` | 日期、说明，字号至少 1rem |
| 主操作 | `#A54218` / 白字 | 主按钮、焦点和选中状态 |
| 按下 | `#853512` | 主按钮 hover / active |
| 选中浅底 | `#FBEEE5` | 已选对象 |
| 成功 | `#356447` | 完成与到账状态 |
| 错误 | `#A42B28` | 输入错误、明确失败 |
| 提醒 | `#825B12` | 待核实、需要关注 |
| 边界 | `#89927F` | 输入框和可点区域边界 |

正文 `1.125rem`，行高 1.6；说明 `1rem`；区块标题 `1.25rem`；页面标题 `1.5rem`；金额 `2rem` 起。系统中文字体，数字使用等宽数字属性。金额保持深色，不靠红绿表达收入支出。可切换更大文字；字号使用 rem，重要信息容许换行。

主按钮最小高 56px，其他触控区域至少 48px；输入框最小高 56px。组件高度随文字增长，不能用固定高度裁字。边距以 4 / 8 / 12 / 16 / 24 / 32px 为基础。卡片圆角 16px，按钮 12px。明确焦点轮廓；选中、失败、等待均有文字，颜色只是辅助。

## 信息与组件的对应关系

| 用户正在做什么 | 合适的组件 | 内容规则 |
|---|---|---|
| 发起需求 | 对话内快捷说法 + 底部工具抽屉 | 点击向同一段对话表达需求，不跳转到独立业务首页 |
| 选账户或收款人 | 搜索框 + 大行距选择列表 | 名称/备注、银行、尾号同屏；账户带余额；不预选不确定的对象 |
| 新增本次收款人 | 独立的就地表单 | 姓名、卡号分开；核对服务端结果后回填。保存为常用需独立接口 |
| 填金额、日期、地址 | 对应输入控件 | 始终有标签；金额使用小数键盘，联系电话使用电话键盘；错误贴近字段 |
| 查看账单 | 月份/账户筛选 + 分类列表 | 总额与统计范围一起显示；普通明细原地展开 |
| 阅读长详情 | 手机抽屉 / 电脑侧栏 | 保留原记录和滚动位置；标题、关闭和内容区清楚分离 |
| 核对敏感操作 | 页面内确认清单 | 收款人、付款卡、金额、费用、时间及实际影响；一个主按钮 |
| 验证身份 | 独立验证表单 | 密码/验证码使用专用输入；错误、重试入口留在表单里 |
| 等待结果 | 循环进度条 + 当前阶段 | “银行正在处理，结果会显示在这里。”保留办理摘要 |
| 查看结果 | 持久回执 | 对象、金额、实际结果、时间、下一步直接展示；长编号按需打开 |
| 临时反馈 | Toast | 普通反馈可短暂显示；交易结果、错误和待办留在页面上 |
| 继续未办完的事情 | 恢复摘要 + 继续按钮 | 找回原任务；由现有流程核实原操作 |
| 多步骤生活安排 | 总览 + 当前步骤 + 分项结果 | 已完成、当前待办、尚待处理分开；支持回看整体目标 |

## 布局与操作约定

手机宽度 320px 起可使用，390px 为主要设计视口。页面只保留一处主要滚动区；长清单可以在抽屉里独立滚动。主要动作靠近当前表单，必要时吸附底部并预留安全区，不能盖住输入、错误或最后一条记录。软键盘弹出时表单仍可滚动。

电脑沿用居中的对话工作区，宽度约 45rem；查资料与办理记录使用右侧抽屉。手机采用底部抽屉。两种尺寸共享消息、任务和草稿。

助手回复直接显示在对话正文。每个任务只有一份可操作卡片，跟随最新的相关回复；展开详情本身不移动卡片。输入过程中查询其他资料，原任务保留在“正在办”；多个未完成任务可从“记录”继续。新的消息到达时，仅在用户已处于最新位置才自动滚动。旧确认保留只读限制。

转账只展开当前要填的步骤，顺序为收款人、金额、付款卡；已有值直接展示并可修改。确认前显示完整核对单，修改入口与核对内容相邻。自由文本原样交给服务端 Agent，点击使用既有草稿或卡片动作接口；前端不解析真实交易意图。

## 状态与文案

每项业务覆盖：初始、加载、空数据、有数据、填写错误、待核对、验证、处理中、成功、明确失败、结果待核实、断线、恢复、登录过期。失败说清具体原因和可执行的下一步；未知结果保留核实入口。

| 场景 | 推荐表达 |
|---|---|
| 选择 | “转给谁？” / “请选择付款银行卡。” |
| 填写 | “这次转多少钱？” |
| 修改 | “资料改好了，请再核对一下。” |
| 恢复 | “已找回上次的内容，可以接着办。” |
| 等待 | “银行正在处理，结果会显示在这里。” |
| 失败 | 使用银行返回的具体原因，配“修改资料”或“查看这笔进度”等实际入口 |
| 查询失败 | “暂时没读到资料，请再试一次。” |

先讲结果，再给下一步；优先一句话。按钮直接写动作，避免“确定”“提交”单独使用。不枚举没有发生的 B/C/D。真实风险和退款范围仍需准确说明，按当前问题简短呈现。前端不改写银行事实；后端固定回复与模型回复另有来源，需要分别整改。

## 无障碍与动效

- 正文对比度至少 4.5:1；边界和焦点至少 3:1。重要动作同时支持键盘、触摸和读屏。
- 打开抽屉将焦点移入，Tab 留在当前层；关闭后回到触发按钮。抽屉标题必须可被读屏识别。
- 错误与对应输入建立描述关系；读屏只播报必要状态，避免整页重复播报。
- 支持 200% 放大、窄屏换行、系统减少动画设置。等待时用轻量动画；不做假进度和装饰性数字增长。
- 以实际手机软键盘、读屏和老人使用走查补齐验证，组件测试不能替代这些检查。
