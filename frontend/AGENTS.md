# 前端 AI 开发规则

本目录由梁爽主导、六水协助。开工读[前端工作顺序](../docs/principles/03-review-and-merge.md#前端设计与后端接入)、[公共契约第 6 章](../docs/contracts/公共契约-2026-09-23.md)及本目录 `README.md`。

v0.3临时安排（2026-10-01）：梁爽、六水仅交一份普通转账关键流程原型图；Erwin负责简易前端和真实接口联调。完整前端在后续阶段接入替换；长期归属及安全边界不变。简易前端已交付；后续完整前端实现仍按票推进。

1. 后续完整前端先做银发用户核心任务调查，形成适老化体验与视觉规范；再做聊天、等待、确认 / 验证、结果 / 报告的原型，走查后实现页面。
2. 页面先用符合现行契约的假数据跑通，再接 Erwin 的纵向样例和真实 API。前端只展示状态、收集用户动作；权限与交易执行由后端决定。
3. 复用公共契约导出的类型。发现 API 缺口时按[公共改动流程](../docs/principles/03-review-and-merge.md#公共底座与-api-改动)提问题，由公共目录负责人修改契约和接口。
4. 前端功能和业务模块功能分开提 PR；涉及确认或验证的交互请 Ringo 审查，联调结果由 Erwin 验收。
