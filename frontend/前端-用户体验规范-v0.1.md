# 前端用户体验规范 v0.1

> 最后更新：2026-10-01 ｜ 主笔：六水（协助梁爽）｜ 状态：草稿 v0.1
> 定位：管**「怎么用」**——每个交互的触发、反馈、状态流转、话术。配合《前端设计规范 v0.1》（管「长什么样」）一起看。
> 手机优先 · 适老化 · 以聊天为主。

## 0. 核心交互模型（一句话）

**用户说 / 打字 → AI 回话 → 必要时弹「引导卡片 / 确认单」→ 用户点 → 结果卡片。**

全程在一条聊天流里走完，不跳页面、不弹窗把用户带离对话。

---

## 1. 语音输入（前端行为）

| 环节 | 行为 |
|---|---|
| 触发 | 话筒**长按说话，松开结束**；停顿自动停 |
| 录音中 | 大字「正在听，您请说…」+ 跳动波形，**不能静默** |
| 转写 | 文字回填输入框，18px、**可点改**（金额 / 名字错了必须能改） |
| 失败 | 「没听清，您再说一遍」或「点这里打字也行」，永远留打字后路 |
| 演示期 | 先做「假转写」（话筒 UI + 预设文字），接 ASR 后替换，后端契约不动 |

---

## 2. 引导卡片（降认知负担）

- **什么时候弹**：AI 判断用户意图模糊、或一个问法有好几种可能 → 先正常回答，回答下面再弹 1～2 张卡片。
- **卡片上写什么**：把可能想问的问题写成选项，如「你是不是想问：这个月花了多少 / 餐饮花了多少」。
- **怎么选**：点卡片，或者**说「第一个」**，两条路都通。
- **红线**：只给选项，**不默认替用户选**（契约硬规则）。

---

## 3. 状态与反馈（四种等待态 + 回执）

| 状态 | 前端展示 |
|---|---|
| 处理中 | 进度条 +「正在帮您办，稍等」 |
| 等您补充 / 等您确认 | 高亮卡片，等用户点 / 说 |
| 结果待核实 | 警示色标签 + 「查询结果」按钮（只查不重发） |
| 成功 / 失败 | 结果卡 + 口语化回执 |

**回执话术（口语化，不用术语）**：

- 成功：✅「已经办好了，500 块转给妈妈了。」
- 失败：❌「这笔钱没转出去，因为余额不够，还差 200 块。」
- 待核实：⚠️「这笔转账的结果我暂时没查到，我没有再转一次。点这里再查一下。」

---

## 4. 确认 / 验证流程（三个安全交互的前端行为）

| 交互 | 前端做什么 |
|---|---|
| 确认单 | 展示关键要素（收款人 / 金额 / 账户）→ 用户点「确认办理」或「取消」；**聊天里说「确认」不算数，必须点按钮** |
| 验证码 | 专用 6 位大格输入 → 提交；上方「模拟验证码」提示区；**绝不出现在聊天气泡** |
| 模拟人脸 | 展示「模拟成功 / 模拟失败」按钮，由**管理员操作**，前端按钮不能直接制造通过 |

---

## 5. 错误与异常兜底

| 情况 | 行为 |
|---|---|
| 断线 / 掉线 | 重连后自动补齐历史，不重发刚才的资金操作 |
| 会话过期 | 提示「演示登录已过期，点这里重新进入」，旧按钮点不动 |
| 操作失败 | 说人话 + 给下一步（换个数 / 补信息），不把用户晾着 |

---

## 6. 适老化交互细节

1. 反馈要**即时**：每点一下都有反应，不让老人以为「没点着」。
2. 一次一件事：一个屏幕只处理一个动作。
3. 语音播报：P1，待定（10-05 前决定）。

---

## 待确认（回「行」或「改 X」）

1. 语音触发：默认「长按 + 说完自动停」→ 行 / 改？
2. 引导卡片数量：默认一次最多 2 张 → 行 / 改？
3. 演示期语音：默认先做「话筒 UI + 预设文字」假转写 → 行 / 改？
