## Problem Statement
用户不知道收款人却被要求填写；聊天问句被当字段；修改依赖内部账户编号；失败与刷新缺反馈。既有票15记录现场，用户已批准本聊天六部分改进方案并授权实施。

## Solution / User Stories
- UX01：常用业务入口可点击；银行卡、收款人可查可选，展示名称、尾号、银行及查询时余额。
- UX02：办理卡持续展示已知金额、付款账户、收款人；逐项补充、修改，查询不中断原任务。
- UX03：聊天始终按自然语言意图处理，提问不被自动填入字段；有歧义时用具体任务卡澄清。
- UX04：收款人支持列表、搜索、无匹配反馈和专用新收款资料填写；不能自动默认选择或暴露完整凭据。
- UX05：修改保留原任务，旧确认失效、新确认必须再次批准；提交后只能查原结果。
- UX06：操作显示处理中/成功/失败/待核实；刷新也反馈。网络异常保留草稿，不把超时当失败、不重新转账。
- UX07：账单显示自然日期及可改查询范围；单笔提供核对入口；空、失败和信息不足分别表述。
- UX08：订阅显示商户、周期、扣款卡及下次日期，退订后重新查询当前清单；旧查询标明时点。
- UX09：具体任务标题、可定位待办、状态更新提示；历史折叠不隐藏当前动作。大字大按钮、窄屏和键盘可用；真实语音未接入不呈现录音承诺。
- UX10：完成后提供真实回执与最新资料查询；所有钱和签约的事实以银行返回为准。

## Implementation Decisions
复用现有公开数据结构、确认/验证、受控银行读取、版本校验及幂等。任务内只读选项是兼容扩展；草稿更新支持未提交的补充阶段和确认阶段，不允许验证中或结果未知时修改。自然语言走现有理解与续办链，专用输入卡只收字段；不靠问号关键词猜测全部用户意图。错误统一翻译并明确下一步，不编造余额、原因或交易成功。

## Testing Decisions
HTTP测试接真实模块、安全门和隔离模拟银行，模型替身只证明程序行为。前端行为测试覆盖选择、聊天求助、修改、反馈、断连与重试。真实模型/HTTP/浏览器证据另记；不操作用户现有演示任务或重置其数据库。成功、失败、待核实、旧确认、跨用户/会话、重复提交纳入验证。

## Out of Scope
生产银行、部署、新语音服务、新安全策略、未来联动场景、专业安全认证。不得为通过验证而放宽风险门。
