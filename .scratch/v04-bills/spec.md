# v0.4 账单纵向场景规格（v04-bills）

> Status: Confirmed — 2026-10-11 随 v0.4 正式启动建立
> 场景负责人：Erwin（登记与联合验收）；账单业务与评测 Owner：周恩宇；前端账单插槽：梁爽/六水（见 [frontend-complete/01](../frontend-complete/packages/01-v04-complete-frontend.md)）
> 版本：v0.4（[需求](../../docs/versions/v0.4.0/requirements.md)；联动移至 v0.5）

## 1. 目的

在 v0.3 已验证的纵向框架（同一 Harness、契约、安全入口、银行接缝和审计）上完成账单分析业务线：用户用自然语言查账、识别异常、生成报告并导出，账单结论有流水依据，权限与导出规则正确，前端转账+账单双场景可用。

本规格只界定当前里程碑的交付范围与验收；账单业务规则以冻结文档为唯一事实源，不在此复制或改写。

## 2. 事实来源

- [02 账单分析 PRD](../../docs/prd/02-账单分析-PRD-2026-09-23.md)：三类公开能力、业务规则与验收例。
- [公共契约](../../docs/contracts/公共契约-2026-09-23.md) §5（模块间调用与 M 系列验收）、§6（前端链路，见 §6.2 六条链路表）。
- [evals/bills/ 21 条代表性用例](../../evals/bills/)（[PR #61](https://github.com/DrErwin/hackerthon-bank-agent/pull/61) 已合入，待运行）。
- [评测集编写指南](../../evals/README.md)：覆盖方法、数量下限与运行报告归档。

冲突时以 PRD 与公共契约为准；发现缺口按公共改动流程登记，不在本场景内改写公共定义。

## 3. 本里程碑要证明什么

1. 账单能力复用 v0.3 公共框架接入，不另建运行体系。
2. 账单结论（数字、分类、异常判断）可追溯到真实交易流水；查询失败或数据不足时不编造数字。
3. 一级读取（本人账单查询/报告）登录即可；账单明细导出必须再次身份验证；越权被拒绝。
4. 异常识别只提示与解释，不把"疑似"说成"已确认"，不代用户执行场景 04/05。
5. 商户/收款方名称不打码、账号打码（PRD 冻结口径）。
6. 前端账单插槽接入后双场景（转账+账单）可用，替换简易前端不回退已验证闭环。

## 4. 核心验收场景

编号 `BF01` 起；用例细化落入 `evals/bills/`（用例编号沿用 `BILL-xxx` 体系），并与 02 PRD 验收例对照。

| 编号 | 场景 | 通过条件 |
|---|---|---|
| BF01 | 查询与分类统计主路径（含口语化时间/金额表达） | 只读调用；金额、口径与流水可复算一致；无写副作用 |
| BF02 | 异常识别（大额突变/陌生收款方/深夜/重复扣款，命中与不命中分开） | 命中给出解释与依据；不误报边界例；不代用户执行处置 |
| BF03 | 月度/年度报告（总览/分类/对比；范围不足或超 24 个月诉求） | 报告有流水依据；范围不足如实说明，不编数字 |
| BF04 | 导出与权限（报告卡片普通导出；明细导出再验证：成功/失败/过期/越权） | 明细导出未过验证不给出内容；越权拒绝；脱敏口径正确 |
| BF05 | 缺信息追问与口径纠正 | 时间范围/口径不明时只追问缺项；纠正后不再用旧口径 |
| BF06 | 中断与恢复（查询中断恢复原任务；流水查询失败/数据不完整） | 恢复同一任务不新建；失败/缺数据如实呈现，不编数字 |
| BF07 | 前端账单插槽走查 | 双场景前端可用（对齐 [FE-02](../frontend-complete/spec.md)）；结果展示与后端返回一致 |

覆盖框架沿用[评测指南 §三](../../evals/README.md)六方向；完整规模下限：每功能至少 10 条、每类异常至少 3 条；运行证据按 §六归档 `evals/bills/evidence/`。

## 5. 完成标准

- BF01—BF07 全部通过并有可复核证据。
- 账单模块只调用公开能力，不访问其他模块私有工具或银行表。
- 涉及资金的跨场景动作逐笔过确认（本场景内账单为只读+导出，无资金动作；导出明细按 PRD 再验证）。
- 评测达到下限并实跑；文档、自动化、运行结果分别记录。
- 前端替换简易前端后，v0.3 已验证的确认、验证、恢复、防重复闭环不回退。
