## 核心验收场景（均未运行）

下述金额是条件例子，不代表当前演示库实测值；每次以L01及银行原回执核对。

| 编号 / 核心映射 | 实际操作与观察点 | 必须成立 |
|---|---|---|
| BE01 / XL-B07、X02 | 原任务显示scope/purpose/limit/used/remaining；用真实当前F10采用，重复原请求；再让模型提交相同选项作对照 | 仅真实原来源+当前完整候选形成一个稳定版本；模型对照零采用；采用本身零资金写入 |
| BE02 / XL-B01/B03/B07 | 个人3000、账单2600、其他未消费占用100，本次上限500；尝试采用生日方案 | 可新增仅300，不冻结500、不自动缩300或提额。用户明确调整后重新核对；个人remaining保持400，G/O另列 |
| BE03 / XL-B01 | 个人余量足够、上限500，按原单件花199+蛋糕268逐动作确认/验证 | 冻结500、消费467、释放33直接与银行对账；used/G/O按交易编号仅计一次；不是现实送达 |
| BE04 / XL-B07、X02—X05 | 省略引用、其他主体/轮次/旧版/账户/期间不符；同预算改版后原任务恢复；多条可能适用或用途不清 | 省略不能绕过；不自动挑大额度、不自动跳新版；旧版在途占用继续计，原查询/限定收尾可做 |
| BE05 / XL-B05/B06 | 冻结/付款未知后取消；释放未知/拒绝；重开及原号回查 | pending先于银行，未知占用保留；停止后零新增购买、不抢先释放；核实后只原授权收尾，未验证不记结清 |
| BE06 / XL-B07、X02 | 两任务同预算竞争；一方核销落账，另一方尝试以旧窗口登记；账单晚反映与closed历史对照 | 同一支持进程串行复核+真实storage事务，已用/G/O不漏不双算；缺金额/归属/覆盖完整性暂停 |
| BE07 / XL-B07、X05 | 采用记录写入前/后、任务结果/HTTP receipt前中断；取消或superseded后重放原请求 | 原attempt/时间/版本/参数不重造；已发生采用只读补原请求结果，当前新计划/取消状态不被覆盖，无新购买 |
| BE08 / XL-B07/B03 | 无个人预算时已冻结，另一任务首次采用；原任务准备下单 | 先明确绑定并据真实未消费冻结登记占用；不足或无事实仅查原号/收尾，不因为已经冻结绕过新约束 |

完整验证还按BG01—BG24覆盖零上限、原时间精度、受控引用隔离、modify/decline、连续版本、summary A/details/summary B稳定与变化、
scope外旧消费、缺失公开结算投影、权限/会话拒绝。不可用故障入口不靠手改共享数据库或预设成功响应顶替。

## 证据与判定

逐场景保存：精确代码head、前置版本、绝对隔离路径、原F10请求/交互/业务plan版本、来源受控记录关联、
采用/占用前后公开事实、真实L01范围及source_as_of、原bank operation/transaction/freeze/order编号、写入次数、
HTTP/页面实际结果和脱敏轨迹。验证码、配送原文、凭据不进入普通证据。

区分开发的替身单元/模块验证、真实存储/来源、真实只读L01、真实资金链、模型/HTTP/页面与本人安全接受。
局部通过不合并为E2E通过；风险事实不足、页面未就绪或缺故障注入时如实Blocked，保留原失败和下次入口。
Erwin运行后将结果交原E2E票汇总，当前版本进度/最终合入仍由中控维护；本轮无实际E2E结论。
