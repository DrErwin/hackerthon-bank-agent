## 业务结果

v0.3 的简易前端只验证了转账一条链路。本工作线交付可运行的完整前端（React + Vite + TypeScript，类型复用公共契约导出），按「通用底盘 + 业务线插槽」组织，替换简易前端，并让后续业务线能以小增量接入、不重做底盘。

## 结构模型：底盘 + 插槽

- **通用底盘**（业务线无关，一次建成，全场景复用）：对话界面、等待与进度、确认单、验证码与模拟人脸等安全确认交互、结果与报告卡片、刷新恢复、适老化。接口面 = [公共契约第 6 章](../../docs/contracts/公共契约-2026-09-23.md)五链路（聊天 / 确认 / 验证 / 报告 / 事件与恢复）。前端只展示状态、收集用户动作；权限与交易执行由后端决定。
- **业务线插槽**（每线一根，同一模板）：该线的业务卡片形态、结果与报告展示、需过确认门的动作清单。已排期插槽：

| 插槽 | 版本 | 业务口径来源 |
|---|---|---|
| 转账 | v0.4 | [01 智能转账 PRD](../../docs/prd/01-智能转账-PRD-2026-09-23.md) · [普通转账纵向场景规格](../transfer-agent-framework/spec.md) · 原型与简易前端为参照 |
| 账单 | v0.4 | [02 账单分析 PRD](../../docs/prd/02-账单分析-PRD-2026-09-23.md) · 账单公开能力契约（第 5 章） |
| 联动 | v0.5 | [06 跨场景联动 PRD](../../docs/prd/06-跨场景联动-PRD-2026-09-23.md)（已冻结；2026-10-11 移至 v0.5） |

## 核心验收场景

编号 `FE-01` 起，作为本工作线交付包的共同验收依据；各业务线的业务口径引用各自 PRD、场景规格与评测目录，不在此复制。

| 编号 | 场景 | 验收要点 |
|---|---|---|
| FE-01 | 转账主路径 | 聊天 → 收款人候选 → 确认单 → 验证 → 结果全程可用；结果只认后端返回 |
| FE-02 | 账单场景 | 账单三类能力入口与报告展示可用；报告数据以账单公开能力返回为准 |
| FE-03 | 中断恢复 | 刷新 / 重启后原任务继续，进度与状态如实呈现 |
| FE-04 | 误操作与过期 | 旧确认、过期确认、重复点击如实呈现，不产生重复提交 |
| FE-05 | 替换回归 | 替换简易前端后重跑确认、验证、刷新恢复、重复点击与真实结果展示；已验证的安全与资金闭环不回退 |
| FE-06 | 适老化走查 | 按[前端-设计规范-v0.1](../../frontend/前端-设计规范-v0.1.md)与[前端-用户体验规范-v0.1](../../frontend/前端-用户体验规范-v0.1.md)走查 |

## 增量规则（新业务线随时加任务）

1. 新业务线 PPRD 定稿后，由场景负责人在本目录 `packages/` 追加「业务线X前端接入」小包（编号顺延），`Start when` 写明 PPRD 冻结与该线接口形态冻结；不重开既有包，不扩大既有包验收边界。
2. 目录负责人在自己工作组按下一未用编号加票；新任务进来先收尾手头票（一票一 PR），再切新任务。
3. 联动插槽（v0.5）按同一方式追加小包，保持各包验收边界独立。
4. 本目录交付包与票据的标识、编号和跨组引用遵守[票据标识规范](../../docs/agents/issue-tracker.md)。
