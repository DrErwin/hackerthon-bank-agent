## 范围与验收

沿用用户已满意的对话原型、配色、字号与组件系统，扩展全部现有用户前台；保留管理/历史开发入口用途。业务事实、选项、确认、验证、结果继续由现行 API 提供。

- F01：自由对话、查资料、继续办理、办理记录共享上下文；已填字段保持可见；大字偏好刷新后保留。
- F02：账户/收款人查询可搜索、查看和带回正在办理的转账，未找到有明确提示。
- F03：账单先展示金额与统计范围，月份筛选、分类、单笔、长明细和刷新可连续使用。
- F04：自动扣费按状态呈现；取消一项后能看清本次结果，再继续办理另一项；只依据实际子任务结果更新展示。
- F05：转账/退订核对、验证码、模拟人脸、成功/失败/未知回执，重要资料直接可读，操作与文字简短一致。
- F06：生活安排展示总体目标、当前步骤、后续步骤、分项事实；配送表单贴近字段提示、受控接口与敏感字段清理保持。
- F07：等待、失败重试、断线、恢复、登录过期、空状态有下一步，恢复读取原任务。
- F08：手机与电脑、长内容、大字、键盘、抽屉焦点检查；用户指定 GPT-6.1-sol 子代理完成浏览器 E2E，缺陷修后复验。

## 验证

使用现有组件/数据源测试，针对改变的行为补回归；全套前端测试及两种构建。浏览器实际点击和输入覆盖主要用户流程，区分契约演示、真实 API、真实模型证据。待子代理检查后记录具体页面、动作、发现与修复，不将截图或脚本通过写成真实模型接受。

## 边界

一票一个 frontend 目录；`.scratch` 保存规格与证据。前端自由文字原样传给 Agent，卡片调用现有接口；不改后端理解、确认门、银行规则、模型配置。真实接口缺陷按目录记录与交接。此授权覆盖实现和检查，不作自动合并或真人签核。
