## Acceptance criteria

- [ ] 实施前确认商品、配送输入、订单/付款/资金收尾的具体页面和文案。
- [ ] 商品/数量/价格/时间变化会显示新方案；旧确认不可用于新参数，原文配送走专用 API。
- [ ] 订单创建、未付款/已付款/未知、已释放/待释放分别展示；不宣称现实送达、退款或订单已取消。
- [ ] 刷新/断线仍可核对原结果与待处理项；实际键盘、200% 缩放与读屏反馈留证。

## 执行与回交

1. 在前端 01 总览上设计商品选择、配送专用录入、冻结条款/确认、逐项下单/付款、收尾及未知状态；给出实际文案，记录 Erwin 走查。
2. 接当前服务端返回的商品、报价、时间和有效动作。价格/数量/方案变化只采用后端的新版本，不能沿用旧确认或在前端决定预算通过。
3. 配送原文通过受控 API 提交；后续使用引用/掩码，不回显到聊天或普通日志。接口不支持的资料修改/取消行为提缺口，不猜造字段。
4. 分开显示订单创建、支付、冻结与释放结果；清楚呈现后端给出的冻结、消费、释放金额。停止后仅显示受控收尾进度，不能额外创建释放确认或宣称退款/送达。
5. 保留双因子验证、结果未知与刷新恢复入口；沿原操作查询，安全停止后不恢复购买。独立 PR 交付后回交 E2E 03/安全 02。
