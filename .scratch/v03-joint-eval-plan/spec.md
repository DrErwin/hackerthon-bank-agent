## Problem Statement

功能和安全用例重复创建相似转账任务，全量使用真实模型会为期限、重传、错误次数等程序分支重复付费。用户已同意共用执行流程，要求明确真实模型的用例数和执行轮次。

## Solution

保留已有用例编号及独立判定，建立普通转账当前版本的联合执行清单。模型理解、授权相关话术、攻击及少量完整流程使用真实模型；确定性规则继续独立离线验证。兼容条件完全相同才共用一次运行证据，不把相近标题当成相同用例。

## Core scenarios

- J01：真实模型重点清单覆盖不同意图、缺项、歧义、改口、确认话术及代表性完整流程。
- J02：同一实际运行可关联功能与安全编号，额外观察要求独立判定。
- J03：正常、失败、到期、重传、越权等程序分支保持独立状态和结果。
- J04：区分当前可执行轮次、待接入安全轮次及后续业务轮次；用例执行数不等于供应商 API 请求数。

## Implementation Decisions

本次仅整理 Markdown 用例编排和可复制运行命令。沿用现有功能 CLI 的样本选择能力，不实现安全适配器、不改后端、模型提示词、契约或业务规则，不调用真实模型。两张文档票分别只修改各自评测目录；规格与票据在本目录。

## Testing Decisions

核对全部功能编号、主场景/样本差异、安全参数位置及重复轮次。验证计算与执行命令一致；共用关系注明前置条件、差异及证据缺口。只检查内容、链接、格式和差异空白，不运行 CI 或全量程序测试。

## Out of Scope

安全自动化接入、补齐原安全集覆盖缺口、真实模型实跑、专业签核、v0.3 验收、账单及联动能力开发。原 151 场景/153 功能样本及 118 安全主用例保留；重点清单不把未实跑样本改为 Passed。
