## Problem Statement

正式整体重置已有公共模型和 API 协调，但当前独立管理页没有入口，演示者不能先核对影响、再次确认，再查询同一次重置。断线或部分失败后若重新建单，会掩盖尚未完成的原操作。

## Solution

在现有 `/admin` 增加一张管理重置卡，复用现有样式。F30 返回的实际影响完整展示，管理员再次确认后才提交 F31。保留原 F31 请求及返回的管理号；F32 永远只读，继续必须重用原 F31。只有整体 succeeded 才显示新轮次及重新进入用户页提示。

## User Stories / 核心场景

- R01：管理员查看当前会话轮次的重置影响；预览不调用执行接口。
- R02：管理员核对影响并再次明确确认，避免直接清数据。
- R03：在途 running 和部分失败显示真实阶段、原因及原管理号；查询只读，继续沿原请求。
- R04：响应丢失或页面刷新后找回原请求，不自动重置，不另建一次重置。
- R05：整体成功后才展示新轮次；用户必须重新进入，下一次重置要先建立新轮次管理员会话。
- R06：普通用户没有重置入口，真实管理授权仍由后端逐次决定。

## Implementation Decisions

- 引用公共契约 §6.8 F30/F31/F32；生成现有 Python 公共模型的前端类型，不复制另一份契约。
- 当前轮次来自管理员 SessionView，不增加 F25；不接 F29。
- 本机仅保存管理请求、轮次、确认引用和管理状态，不保存管理员密钥或用户资料；发出 F31 前先持久保存原请求。保存失败不发出重置。
- 状态恢复不会自动发送写请求。已发出 F31 后不提供放弃记录/新建重置入口。
- 契约测试响应模式明确说明本入口需真实 API，不伪造整体重置成功。

## Testing Decisions

最高已有接缝为管理页组件 + 模拟 HTTP 边界，验证用户动作和出站调用。覆盖 R01—R06、重复点击、断线、刷新、原号续做、只读查询、会话过期、存储失败；不测试实现内部字段。末尾运行受影响回归和前端全集，真实 API 与 contract-demo 两构建。
