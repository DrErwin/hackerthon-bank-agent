# B26 管理重置入口：局部验证

日期：2026-10-27。实施范围仅 `frontend/`；本组记录不替代整体 B26、浏览器或真人接受。

## 接口及交互

- 管理页 `/admin` 在后端识别为 admin 后才挂载卡片。当前轮次来自 SessionView；没有添加普通前台入口、F25 或 F29。
- F30 发送 `request_id + demo_round_id`，完整展示返回的 effects。勾选核对后才提交 `request_id + reset_confirmation_id` 到 F31；服务端仍逐次鉴权、消费确认和协调重置。
- F31 发出前先把原请求保存在本机该管理来源的 localStorage。保存失败不提交；网络失败、明确拒绝、running 或 failed 都保留原请求，不提供另建/清除入口。
- 刷新不自动写入。已知管理号由 F32 GET 查询；继续使用逐字段相同的原 F31。F32 不推进重置。
- failed 显示实际原因和阶段，即使结果带新轮次字段，也不提示成功。只有 status=succeeded 才显示新轮次及重新进入用户页；再次预览须先进入对应新轮次管理员会话。
- 仅持久保存管理引用、请求和结果，不存管理密钥或用户资料。contract-demo 明示该入口需真实 API，不模拟重置成功。
