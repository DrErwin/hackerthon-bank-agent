## 业务目的

由转账目录提供原转账在新会话继续的公开能力，未提交回到重新确认，已提交或状态不确定只回查原操作。

## 验收

- [ ] 公开入口验证原、新身份的同用户 / 同轮次 / 原任务关联，不允许任意调用者替换归属。
- [ ] 保留 task_id、原 operation_id、业务参数与执行事实；未提交动作重新确认、按风险重新验证，旧确认 / 验证不能批准新会话提交。
- [ ] 对于已 claimed、processing、unknown 或已提交动作，只查原 operation_id，不重新规划、生成新操作或提交第二次。
- [ ] 补信息、等待确认、等待验证、未提交取消、终态和查询等待分支均有明确恢复结果，现有同会话调用保持兼容。
- [ ] 公开恢复入口覆盖服务重启、转换中断及重复恢复；资金副作用最多一次，跨用户 / 轮次和旧授权被拒绝。
- [ ] 不修改银行规则、安全策略或底座私有状态；确需新公共能力先记录并拆相应目录票。

## 验证入口

转账公开 workflow 入口及现有受控工具接缝，覆盖正常与异常分支。

## 目录边界与交接

一票、一分支、一 PR 只修改本票 Directory；公开能力调用说明、模块文档和测试随本目录交付。本人规格、票据与项目跟踪对应过程条目可按队员开工规范更新。实施若确需额外契约或其他目录改动，先记录缺口并独立拆票，禁止在本票跨目录绕过。

依赖完成标准是前置票实际实现、公开入口可调用且 PR 合入，不能用写完文档代替。当前票只完成正式发布，未领取、未开始实现；最终联合验收仍由原票 12 承担。
