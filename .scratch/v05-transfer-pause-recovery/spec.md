# 提交前风险证据暂停的原任务恢复

Status: in_progress
Owner: Erwin（v0.5）；执行 `/root/transfer_pause_recovery` AI 子代理
Accepted at: 2026-10-29
Package: [v05-cross-linkage/packages/01-platform-bank](../v05-cross-linkage/packages/01-platform-bank.md)

## Problem Statement

实际页面把原500元转账的付款卡由A1改为A5后，安全检查因没有覆盖该组合的风险事实而正确暂停。但原任务的“查看原任务”只重复同一暂停卡，用户既不能改回付款卡，也不能取消未提交的草稿。

根实际红例保存在其本轮页面证据中：`viewOriginal=1 / editTransfer=0 / cancelTransfer=0`。本票不直接修改根正在运行的任务或银行库；原暂停证据不以新成功覆盖。

## Solution

对确定仍在提交前的风险覆盖缺失，保留已填资料并让用户在原任务修改、重新核对或取消。风险证据仍缺时继续暂停；修改后的动作重新核对、确认与验证。其他权限、执行复用、资金未知和冲突状态不扩展动作。

## User Stories

1. 用户在未提交时换错付款卡后，可以保留收款人和金额改回原卡。
2. 用户可以取消这个尚未提交的草稿，不必另建任务来遮盖暂停。
3. 用户原样重新核对时，缺失的风险事实仍然阻止提交。
4. 用户改动资金资料后，旧确认和旧操作不能批准新动作。
5. 银行结果未知或处理中时，用户只能核实原编号，不能借本修补改交易参数。
6. 访问权限、会话恢复、活动资金安排冲突和高风险终止保持原规则。

## Implementation Decisions

- 实施范围仅 `backend/app/modules/transfer/`，引用现有公共状态、交互和裁决字段，不改公共契约、安全提供方或白名单。
- 只在独立普通转账明确调用提交前检查的相位，对 `ADMISSION / PAUSE / DEPENDENCY_UNAVAILABLE`、恰为 `risk-signal-coverage-required` 且绑定当前操作/修订/参数的裁决，使用既有可等待输入与安全重核对路径。
- 执行入口返回相同错误码或 `reused=False` 均不足以证明未提交，不能套用上述分支。
- 原任务修改沿既有字段修订入口，新操作与修订使旧确认不适用；取消不调用银行。
- 旧END兼容只沿准确parent_config；只穿过归属和其他全部状态未变的run_id更新，最终准确前驱必须是同一操作/修订/参数的security节点。当前检查仍为上述目标暂停才发布等待；ALLOW或其他结果不进入submit。缺链、资料变化、submit来源及Cross子任务均不迁移，不以缺回执推断。

## Testing Decisions

复用真实TransferWorkflow及现有Harness/安全/模拟银行接缝。仅风险裁决与规划为明确测试替身，测试外部状态、动作、参数保留、原号与真实写入次数；不以图内字段赋值代替行为验证。

| 场景 | 核心验收 |
|---|---|
| PR01 | A1确认后改A5，风险覆盖缺失进入原任务可编辑等待，无银行提交 |
| PR02 | 原样重核对仍受同一暂停约束，不新增提交 |
| PR03 | 原任务取消成为cancelled且零提交 |
| PR04 | 改回A1保留收款人/金额，重新前检、换新操作/修订并要求新确认 |
| PR05 | 执行相位相同暂停（含reused两种值）不提供新编辑路径 |
| PR06 | 权限、任务状态来源、安排冲突、高风险以及未知/处理中保持原限制 |
| PR07 | 重启/新会话读取当前等待不提交资金，原旧END记录保持其证据边界 |
| PR08 | 公共HTTP真实Harness/安全/银行验证原等待可重核对、取消或修订；旧确认拒绝、新动作仍要求双因子 |

## Out of Scope

前端改动、公共恢复协议、旧无来源检查点的猜测迁移、银行重置、风险白名单扩充、真实模型或页面执行、完整后端重跑、比赛资料、真人安全接受。
