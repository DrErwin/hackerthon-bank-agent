# v0.4 前端 E2E 旅程画板（演示页）

打开方式：直接双击本目录的 `index.html`（纯静态，无需服务器、无需联网；截图在 `assets/`）。

## 这张画板是什么

把 v0.4 完整前端的真实 E2E 流程摊成一张可拖动的白板：

- **转账业务线**：一句话发起 → 确认门 → 验证码 → 银行结果 → 刷新只读，外加取消 / 修改 / 输错 / 重新获取 / 高风险五条分叉。
- **账单业务线**：消费汇总、明细查询、异常核对、月度报告四个功能，按「自然语言 → 选账户 → 结果卡」逐屏展示；异常核对单独展示候选流水选择与两种结果。
- **安全与恢复（横切）**：任务没办完就离开 / 重新进入、恢复后继续、登录过期、旧步骤不复活、结果待核实（例外），以及主入口与回滚路径。
- **手机适老化 390×844**：同一套流程在手机视口逐屏实测。

共 **36 个页面状态 / 7 条分叉**；点任意卡片可看大图、用户操作、系统行为、分叉说明与证据来源。

操作：拖动空白处平移，滚轮上下，Ctrl+滚轮缩放；顶部按钮按业务线聚焦，「总览」看全图。

## 证据口径（诚实标注）

卡片上的标签分三类：

| 标签 | 含义 |
|---|---|
| 真实接口 E2E | 真实 local-demo 后端（GLM Coding Plan `glm-5.3` + 模拟银行）+ 真实前端页面。2026-10-21 为这张画板补拍，或来自票 04 / 05 的既有证据 |
| 评测浏览器 | 离线固定规划器 + 真实安全门/银行的浏览器实测（0 次模型调用），来自 `evals/transfer/evidence/2026-10-21`（TF-OBS-04 / 06 / 07） |
| 组件 / 契约 | 真实组合无法构造的故障，由组件 / 契约测试覆盖（结果待核实） |

未覆盖与已知项照实写在卡片里：

- 异常核对「没有发现需要留意的交易」在规则数据不足时仍用成功色 —— 票 04 审查第 1 条，PM 决定保留现状，画板里标成「已知遗留」。
- 恢复门把原因码 `SESSION_RECONFIRMATION_REQUIRED` 直接显示给用户 —— 可读性问题，本次未改，如实标注。
- OBS-05（切换对话后迟到响应）是单会话前端的评测缺口，PM 已按例外接受。
- 截图里的金额、笔数是运行时刻的真实数据（演示数据会累积，重跑后数字会变）。

本页是**展示层**，不新增验收结论，也不替代票 04 / 05 的证据与 PM 2026-10-21 验收记录；细节以票面和 `docs/versions/v0.4.0/completion.md` 为准。

## 复现与再生成

`_capture/` 是生成脚本（需要本机真实栈：后端 8000、Vite 5173 real-api；`puppeteer-core` 用 `npm i --no-save` 装在 `frontend/node_modules`）：

```powershell
$env:NODE_PATH = 'D:\hackerthon-bank-agent\frontend\node_modules'
node _capture\capture2.cjs modify,highrisk    # 转账分叉分步截图（失败会重试截图，不中断其它流程）
node _capture\capture2.cjs summary,detail,anomaly,report   # 账单分步截图
node _capture\recovery2.cjs                   # 恢复门（待确认时清会话后重新进入；结束会取消任务）
pwsh -NoProfile -File _capture\build-assets.ps1   # 截图归档进 assets/（含从票 04/05 证据复制的历史图）
node _capture\preview.cjs                     # 各业务线预览图（preview/）
node _capture\test-interactions.cjs           # 抽屉/大图/缩放/滚轮自检
```

`raw/` 是原始截图，`preview/` 是自检预览；`index.html` + `assets/` 是交付物。共 35 张截图：第 1 / 2 步共用同一张欢迎页（第 2 步是输入框区域放大）。
