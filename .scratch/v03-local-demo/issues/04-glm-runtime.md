## Acceptance criteria

- [x] 使用既有公开运行组合与 API 工厂装配入口，不复制业务图、安全门或银行规则。
- [x] 模型通过02的标准连接器进入既有规划入口；普通对话返回仅回复，明确转账产生受控候选，模型不执行资金动作。
- [x] 本机读取模型名、普通 API 地址与密钥，默认模型为可配置的glm-4.7；保留配置一致性检查，说明实际 API 服务商及兼容客户端标识。
- [x] 模型密钥、服务端签名秘密和管理密钥不进入仓库、前端构建、日志或模型上下文。
- [x] 缺失配置、连接器不兼容、GLM不可用或无效模型结果有明确失败；不自动全部放行、不静默使用测试模型、不伪造结果。
- [x] 03的权限、风险及人脸管理员授权回调完整装入组合，并能区分普通与管理操作。
- [x] 应用与银行使用固定本机持久路径；重新启动复用数据和秘密，不清空原任务、确认或交易，不重复播种。
- [x] 给出一种可重复的后端启动方式，配置值与前端代理、允许来源、Cookie、事件流及单worker安排一致。
- [x] 在公开 API 层验证模型故障、普通回复、显式转账、确认/验证后单次提交及重启后原结果恢复；测试模型回归和真实GLM调用分别记录。
- [x] 本机凭据可用后记录真实GLM普通回复和明确转账证据；无凭据时明确受阻，不能以测试模型标为真实调用通过。
- [x] 为01提供地址、启动方式、演示数据与可执行路径；API原票10引用实际证据，原票12保留专业评测与AF01—AF14最终验收。
- [x] 实施只改平台目录；工程依赖由02交付，安全配置由03交付，API缺口返回API目录处理。
