## What to build

提供现有运行组合需要的受控权限、风险和管理员人脸授权配置。固定演示主体可以办理本阶段普通转账，其余未授权访问被拒绝；演示用风险事实必须有服务端来源，不能直接使用测试中的全部放行与固定低风险回调。

## Acceptance criteria

- [x] 使用既有回调接口与安全门，不建设新策略平台或修改公共契约。
- [x] 公开普通转账能力和每个已登记私有工具逐次检查固定演示主体、当前轮次及声明权限；未知主体、未声明动作或缺失授权拒绝。
- [x] 管理员人脸授权使用独立可信管理身份，不由普通前端、模型或任意用户编号决定。
- [x] 风险依据现行转账 PRD §9.2与安全字段附件；规则、事实来源和版本可说明，普通请求不能自填最终风险等级。
- [x] 提供可重复的低、中、高风险演示事实，验证既有基础验证、双因子和高风险终止行为；不假定普通演示用户的确认可以放行高风险。
- [x] 不自定尚未确认的金额阈值，不复刻银行余额、限额或交易风控，不把演示事实映射描述成全量诈骗检测。
- [x] 事实不足或现有公开读入口不支持某项判断时明确拒绝/报依赖不可用，并记录具体阻塞；不得默认全部低风险或越目录顺手补能力。
- [x] 验证允许、拒绝、权限缺失、其他用户、无权人脸作答、无确认及风险升级等公开行为；敏感动作仍由安全门核对当前确认和验证记录。
- [x] 返回的回调可供04装配；测试与审查证据说明实际风险覆盖及未覆盖项。
- [x] 实施仅修改安全目录；本票不代 Ringo 给出真人批准，不改变既有合并规则。
