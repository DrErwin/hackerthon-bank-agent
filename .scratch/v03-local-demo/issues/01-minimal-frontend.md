## What to build

本机可运行的简易聊天页面，显示普通回复、候选、当前确认、专用验证、进度和银行结果，支持修改、取消与恢复。先用明确标注的契约测试响应验证页面，后接真实 API；独立管理会话处理模拟人脸与只读时间线。

## Acceptance criteria

- [x] React、Vite、TypeScript 前端可在本机启动，文字和按钮清楚；不要求完整视觉设计系统。
- [x] 普通闲聊显示回复；异步消息受理暂无任务编号时正常等待，不伪造转账或成功。
- [x] 缺项补充、收款人候选与专用资料入口使用当前接口；完整账号不回传聊天。
- [x] 确认卡片展示当前版本完整脱敏要素，正式确认、修改、取消分开；聊天中的“确认”不批准资金动作。
- [x] 验证码独立输入和标注模拟的提示区；不进聊天、模型、日志或客户端持久存储，提交后清除秘密输入。
- [x] 显示模拟人脸等待，由独立管理员会话作答；普通用户不能自授管理身份。
- [x] 成功、失败、取消、处理中、待核实和接口不可用状态如实呈现，只显示后端当前允许的动作。
- [x] 刷新、事件断线与登录过期后找回原任务；新会话显式恢复，旧确认/验证按钮不可用。
- [x] 重传沿用原请求编号；验证码不自动重放；结果未知查询原操作，不新建交易。
- [x] 管理员可按任务查看脱敏只读时间线；管理密钥不编入普通页面或持久保存，普通登录无时间线权限。
- [x] 通过开发代理保持 Cookie、Origin、事件流一致；公共类型引用或从公共模型生成，不另定协议。
- [x] 04 就绪后完成真实 API 页面验证；记录普通回复、AF01主路径及修改、取消、重复点击和恢复证据，银行资金提交最多一次。
- [x] 测试响应和真实接口状态明确区分；真实调用失败不自动回退测试响应。
- [x] 交接启动步骤、测试结果和限制，证据供原票10与原票12引用。测试响应通过不得单独标为本票真实交付完成。
- [x] 实施改动只在归属目录；发现 API 缺口返回对应目录修复，不在页面复制业务或安全规则。
