# audit —— 审计与回放（全系统运行日志）

归属：底座（Erwin）。

放什么：审计事件写入机制（事件外壳、追加写、与工具结果同事务）、按任务的只读时间线、JSON 证据包导出。**审计运行日志全程持久化，敏感原文不落盘**（09-24 拍板）。

边界：**审计规则（记什么 / 脱敏 / 谁可看）由安全侧（Ringo）在安全底座 PRD / 契约第 4 章制定**，本模块只做实现；审计读取端不连接执行入口，不持业务写权限（架构 §9 / §12）。

拆分理由（09-24）：审计事件来自 Harness、LangGraph、执行器、恢复协调多方，是横切面；记录与安全裁决分离，审计才能反过来核查裁决本身。

`AuditJournal` 使用应用 SQLite 路径保存冻结契约的类型化事件和脱敏证据；同一演示轮次、同一运行的序号必须递增。`append` / `append_in_transaction` 的 `evidence` 保存事件外壳快照，`snapshots` 同时保存 payload 引用的其他快照。敏感放行必须先存匹配的授权与参数快照，有副作用的 `tool.started` 必须关联已落盘的放行裁决和参数快照。`append_in_transaction` 接受调用方现有的应用数据库事务，使工具结果与相应审计记录一起提交；写入异常由调用方停止动作，不得忽略。已知秘密仍须通过 `known_secrets` 传入，输入入口负责阻止可疑自由文本进入模型。

`AuditReader` 只读取审计库，不持模型或业务执行入口；每次查看或导出先经服务端注入的授权判定，缺少判定时默认拒绝，并追加 `audit.accessed`。查看者身份由后端可信入口建立，不能取自请求体。JSON 证据包包含事件、外壳与 payload 的脱敏快照、哈希、缺失说明和未配对的开始事件；哈希只用于包内一致性检查，损坏的快照按缺失显示。

`output_guard` 是只读输出探针：`probe_output` 报告 `credential` / `full_account` / `personal_name` / `personal_phone` 命中类别，并返回与 `journal.redact(..., free_text=True)` 一致的脱敏文本；`probe_secrets` 只对认证秘密做导出判定。探针不做放行或拒绝决定。无分隔符的 6 位验证码形状（如「验证码123456」「code: 123456」「123456 是本次登录的验证码」）只报告、不脱敏，出口接线须按 `credential` 命中拦截。6 位数字的凭据形状按**短语相邻**判定，不做距离窗口：`reason_code`、`duration_ms`、UUID 里碰巧出现的 6 位数字等机器载荷不会误报，审计证据包可正常导出（v05-observer-seams/08）。

英文 `password` / `passwd` / `pwd` 标签也复用同一秘密规则（Issue #271）：标签须为独立词，后接冒号、等号或「是/为」以及非空值（含纯符号密码）；不设最短长度。无值提醒（如「请不要把 password 告诉别人」）、空值和相似字段名不命中。探针结果与审计脱敏保持一致，已脱敏值重复检查不报秘密。

从 `backend/` 验证：`python -m pytest -q app/audit/`。脱敏规则和查看范围属于安全侧规则，合入前仍需适用的安全审查；v0.5 按根目录 AGENTS 的 Erwin 代行安排留痕，不记为 Ringo 本人签核。
