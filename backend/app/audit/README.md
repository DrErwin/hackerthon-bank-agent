# audit —— 审计与回放（全系统运行日志）

归属：底座（Erwin）。

放什么：审计事件写入机制（事件外壳、追加写、与工具结果同事务）、按任务的只读时间线、JSON 证据包导出。**审计运行日志全程持久化，敏感原文不落盘**（09-24 拍板）。

边界：**审计规则（记什么 / 脱敏 / 谁可看）由安全侧（Ringo）在安全底座 PRD / 契约第 4 章制定**，本模块只做实现；审计读取端不连接执行入口，不持业务写权限（架构 §9 / §12）。

拆分理由（09-24）：审计事件来自 Harness、LangGraph、执行器、恢复协调多方，是横切面；记录与安全裁决分离，审计才能反过来核查裁决本身。

`AuditJournal` 使用应用 SQLite 路径保存冻结契约的类型化事件和脱敏证据；同一运行的序号必须递增。`append_in_transaction` 接受调用方现有的应用数据库事务，使工具结果与相应审计记录一起提交。敏感动作在授权快照和 `tool.started` 写入成功之前不能提交银行；写入异常由调用方停止动作，不得忽略。所有可能出现的验证码、口令等已知秘密须通过 `known_secrets` 传入写入端，输入入口仍负责阻止自由文本里的秘密进入模型。

`AuditReader` 只读取审计库，不持模型或业务执行入口；每次查看或导出先经服务端注入的授权判定，缺少判定时默认拒绝，并追加 `audit.accessed`。查看者身份由后端可信入口建立，不能取自请求体。JSON 证据包包含事件、脱敏内容与哈希、缺失说明和未配对的开始事件；哈希只用于包内一致性检查。

从 `backend/` 验证：`python -m pytest -q app/audit/test_journal.py`。脱敏规则和查看范围属于安全侧规则，合入前仍需 Ringo 审查。
