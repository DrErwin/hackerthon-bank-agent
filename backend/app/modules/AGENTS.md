# 业务模块 AI 开发规则

适用于 `transfer/`、`bills/`、`cross/`。每次任务只修改分配给自己的一个模块目录；评测集、公共底座和前端另开各自负责的任务。开工先读当前模块的 `README.md`、PRD，以及[业务并行原则](../../../docs/principles/01-business-parallel.md)和[Review 与合并原则](../../../docs/principles/03-review-and-merge.md)。

1. 一个分支和 PR 只交付一个能演示、能测试的小能力。通过模块注册接入系统，引用现行公共契约。
2. 前一个 PR 未合并时，独立功能从最新 `main` 另开分支；依赖它的功能最多再开一层 Draft PR，并标明依赖。每人同时未合 PR 最多 2 个。具体操作见[业务并行原则 §2](../../../docs/principles/01-business-parallel.md#2-分支与并行)。
3. 发现公共契约、底座或平台 API 缺口，先按[公共改动流程](../../../docs/principles/03-review-and-merge.md#公共底座与-api-改动)记录问题，由对应目录负责人修改。模块内可用符合现行契约的假实现继续验证。
4. 提 PR 前更新本模块清单和公开能力文档，声明工具的权限、副作用与确认策略，并运行正常、关键分支、拒绝和异常用例；涉及暂停的能力还要验证恢复。
5. 需要操作资金或其他敏感动作时，走统一确认和执行入口。银行事实以模拟银行返回为准。
