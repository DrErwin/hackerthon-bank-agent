# security —— 安全底座

归属：安全（Ringo）。

放什么：策略、统一工具执行器、确认门、权限枚举、**审计规则**（记什么 / 脱敏 / 谁可看；写入与查看端在 `../audit/`）。开发原则见 [02-security-platform](../../../docs/principles/02-security-platform.md)。

边界：不编写业务 SOP，不复刻银行限额 / 余额 / 风控规则，不替代银行做交易最终判定。

## v0.3 最小执行门

`gate.py` 提供普通转账纵向链路所需的四个接缝：

- `ToolRegistry`：注册工具时校验权限、操作等级、副作用和逐动作确认策略；未注册工具默认阻断。
- `ConfirmationService`：只接受结构化按钮答案，绑定服务端用户、会话、轮次、任务、动作版本和参数快照；确认有效期固定为一小时，重复同答案返回原决定。确认版本和执行认领保存在应用 SQLite 中，服务重启后仍然有效。
- `SecurityGate`：先核对可信作用域和任务状态，再检查动作绑定、后端风险、当前确认和银行验证记录，返回冻结契约的六种裁决之一。确认和验证交互只引用由后端创建的真实记录。低风险资金动作需要同会话基础验证，中风险只接受绑定当前动作版本的验证码与模拟人脸双因子记录，高风险直接阻断。
- `DeterministicExecutor`：只执行 `allow` 的已注册处理器；实际参数只按 `parameters_ref` 从后端受控快照读取，调用方不能在确认后替换参数；提交前以同一数据库事务认领操作并锁定确认，取消与执行只有一方能成功。重复请求和服务重启只按原操作编号回查银行结果；`not_found` 与查询失败都保留待核实状态，不能重新调用资金处理器。

风险判断、权限与资源归属、任务终止状态、确认与验证记录创建、银行验证记录读取、脱敏授权快照保存和安全裁决写入均由后端注入的确定性回调提供。模型、聊天文字和前端布尔值不能直接生成这些可信事实。敏感动作在授权快照或裁决记录写入失败时暂停，不调用工具。

当前实现只覆盖票 #07 的普通转账最小门槛；限定释放、完整策略检测器和后续业务安全规则仍按各自里程碑实现。本实现尚需 Ringo 的安全评测与代码审查，不能据此标记票据完成。
