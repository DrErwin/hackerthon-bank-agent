### 5.1 硬冲突（同一件事，两份文档说法不同）——9 条

**X1 · 06 到底直不直连银行？** ⚡ 架构已有答案，快过
- **背景**：全系统只有模拟银行会"管钱"（冻结、扣款、放回）。06 的生日任务必须先把预算冻住再花，所以它一定要用银行的资金能力。
- **对不上在哪**：06 PRD（§3.2）写"06 **不直连银行**"；Mock Bank PRD 又把 06 写成"冻结 / 分笔扣款 / 释放"的使用方。两句放一起，看起来打架。
- **其实架构已定**：架构总图（2026-09-19）里，所有业务模块用银行的**唯一通道**是"银行系统接入层"，谁也不能绕开。06 那句话的本意是"不直接碰银行的账本、不自己抄银行的规则"，只是措辞写猛了。
- **会上要做什么（1 分钟）**：把 06 那句改成"**不直连银行数据库、不复制银行规则**"；确认 06 的资金动作走"接入层 → 银行资金管理域"。
- **9-21 新材料（让这条更确定）**：01 交了 §3.2 对外公开能力 5 项（发起普通转账 / 查询转账任务状态 / 创建或管理定时转账 / 创建或管理 AA 收款 / 获取转账结果摘要），**里面没有"资金预留 / 冻结"**。所以"06 改去调 01 的能力来冻钱"这条路走不通——冻结只有银行能做。措辞改完即可关闭。

**X2 · "找收款人"这个能力落在谁家？**
- **背景**：老人说"给妈妈转 500"，系统得先把"妈妈"变成一个具体账号——这一步叫找收款人。
- **漏在哪**：转账 PRD（附录 A）要"按姓名 / 手机号 / 备注查候选列表"，提供方写着"业务模块；收款人查询服务**或**模拟银行"——三个候选没收敛。而 Mock Bank 能力表里只有"**核验收款人**"（你给我账号 + 姓名，我告诉你对不对），**没有"帮我找哪些人符合"**。核对有了，查找没有。
- **为什么现在定**：这是转账和 06 生日任务的**第一步**，这步不通，后面全卡。
- **会上要做什么**：定候选查询由谁提供。归银行 → Mock Bank 能力表补一行；归业务模块 → 说清数据从哪来（常用收款人名单存在哪、谁来维护）。

**X3 · "这个收款方是不是陌生"怎么拿到？**
- **背景**：账单最重的一条异常规则是"转给从没打过交道的账户 = 高危"。判断的前提是知道"这个账户过去 3 个月有没有交易过"。
- **漏在哪**：Mock Bank 第 4 章写了"陌生账户"的**定义**，但能力表里没有一行能把它**查出来**。账单模块拿不到这个事实。
- **会上要做什么**：定给法。推荐：查流水时每笔直接带一个"**是否陌生**"标记（一次搞定）；备选：单独提供一个查询接口。

**X4 · 账单要的"平时单笔"，银行只给"月均消费"。**
- **背景**：账单判断"这笔是不是花得反常"有两把尺子：①超过过去 3 个月任何一笔（极值）；②超过"平时一笔"的 2 倍。
- **漏在哪**：银行的消费基线只给两个数——月均消费、单笔最高。"月均消费"是一个月**总共**花多少，不是"**平时一笔**花多少"。第二把尺子的分母拿不到。
- **会上要做什么**：二选一——银行基线补一个"**单笔平均**"（推荐，就是多算一个数）；或账单改算法（那 2 倍的阈值要重算）。

**X5 · 流水的分类：银行是两个标签，账单是一本字典。**
- **背景**：账单报告要按类汇总（餐饮花多少、医疗花多少）。银行给每笔流水带**两个标签**：交易性质（消费 / 转账 / 退款 / 利息）+ 商户类别（餐饮 / 医疗 / 购物…）。账单那边只有**一本七类字典**（餐饮 / 交通 / 医疗 / 购物 / 居住 / 转账 / 其他）。
- **对不上在哪**：账单把"转账"当一个**类别**，银行那边"转账"是**性质**不是类别；"退款"在银行的性质里有，账单七类里**没有**。两套模型对不齐，统计会算错或算不出。
- **为什么必须现在定**：这条不定 → D06 定不了 → **09-25 契约冻结过不去**。
- **会上要做什么**：定账单统计用哪套。推荐：银行两个标签都给，账单按"性质 + 类别"组合统计——转账按性质单列，退款按性质抵扣，分类统计只算消费。

**X6 · 账单把用户引到本期不存在的功能。**
- **背景**：账单发现可疑交易后，要给老人指条路："你可以去冻结卡片 / 取消订阅。"
- **漏在哪**：卡片管理（04）和订阅管理（05）**本期没排期**。演示时系统说出的出口不存在，当场穿帮。
- **会上要做什么**：统一改成真话口径。建议："这个功能本期没有，建议拨打银行卡背面的客服电话。"话术由 PM 统一，三份 PRD 用同一句。
- **9-21 进展（六水已做一半）**：02 已把跳转出口标注成"场景 04 卡片管理 / 场景 05 订阅代扣，**本阶段不实现，02 仅声明接口**"——**PRD 层面已经诚实**。剩下的是**用户实际听到的那句话**：PRD 写着"不实现"，不等于回执里会说人话。这条剩下的部分，会上并入 K4 一起定。

**X7 · 联动的确认方式：一处说"待定"，一处已经写死。**
- **背景**：一笔联动任务里有多笔动钱（生日买两样、收入分三笔）。用户确认一次，还是每笔确认一次？安全底座（§19）把这个问题列为**待定**。
- **对不上在哪**：06 PRD 已经写成"用户对当前**完整方案**一次确认"（合并确认），连确认单内容都列好了。相当于把没拍的板当已定的写。
- **为什么必须现在定**：安全底座自己说过"改公共规则的分歧要回父级 PRD 重新评审"。这条不清，安全底座的待确认清单清不掉。

**X8 · 两道安全检查，谁查什么没说清。**
