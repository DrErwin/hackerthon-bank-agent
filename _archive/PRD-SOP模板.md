# PRD 场景 SOP 模板

> 2026-09-18 补充：本轮先按 [初步 PRD 交付要求](初步PRD交付要求.md) 写业务初稿，后续评审按需查阅 [场景 PRD 完整参考清单](场景PRD完整参考清单.md)。本文保留五要素简表与历史示例。下文“直译成流程图”不代表与 LangGraph 程序节点一一对应；示例额度、验证方式与到账时间不作为当前已定规则。

> **给谁用**：负责写业务 PRD 的队友。一个场景填一份，不用写任何技术词汇。
> **什么时候交**：09-18（PRD 截止）。09-25 契约冻结前有疑问可以改，之后不动的部分视为定稿。
> **它去哪**：技术侧会把每份 SOP 直译成系统流程图——你写什么步骤，系统就有什么步骤；你写什么例外，系统就有什么分支。**你就是在定义产品行为本身。**
> 最后更新：2026-09-16

## 一、空白模板（复制这份去填）

```markdown
## 场景：<场景名>              优先级：P0 / P1 / P2

- 一句话目标：<用户说一句什么话，系统帮他办成什么事>

| 字段 | 内容 |
|---|---|
| 触发 | 用户会怎么说？列 3-5 句口语原话，包括模糊、省略的说法 |
| 步骤 | ① …（每步一句话：需要什么信息 / 帮用户做什么）<br>② …<br>③ … |
| 例外 | 信息不够怎么办？办不成怎么办？用户中途反悔怎么办？ |
| 确认点 | 哪几步动钱 / 动敏感信息？确认时给用户看什么（列清楚：收款人？金额？时间？） |
| 回执 | 办完后发给用户的那条消息，照真实样子完整写出来 |
```

**填写粒度**：一个 SOP = 用户的一个完整任务（「转账给妈妈」是一份，「AA 收款」是另一份），不是一个按钮一个 SOP。写不准的例外就写「❓此处不确定」，留给技术侧标记，不要空着。

## 二、填好的示例：场景 01 · 智能转账（P0）

```markdown
- 一句话目标：用户说"给妈妈转 500"，系统核对清楚、用户确认后完成转账并汇报

| 触发 | "给妈妈转 500" / "把上周那笔房租再转一次" / "转 200 到尾号 8888 那张卡" |
| 步骤 | ① 认人：从常用收款人里找"妈妈"；找不到或重名，问一句（重名就列出候选）<br>② 核对：生成一张面单——收款人（姓名打码）、卡号尾号、金额、到账时间<br>③ 确认：把面单给用户，等用户亲口确认<br>④ 执行：转账，拿到结果（成功/失败/处理中）<br>⑤ 自检+回执：核对"实际转出"与"计划"一致后，发回执 |
| 例外 | 金额超 5000 → 先发一个模拟验证码，验证通过才生成面单；收款人重名 → 列候选让用户选；余额不足 → 告知余额并给替代方案（改金额/改时间）；用户说"算了" → 取消并确认已取消 |
| 确认点 | 第③步必须确认。面单必含四样：收款人（姓名打码）·卡号尾号·金额·时间。用户必须回复明确确认（如"确认"），系统绝不把"嗯"之类模糊回答当确认 |
| 回执 | "已转给妈妈（尾号 8888）¥500.00，预计 2 小时内到账。流水号 TX20260916…" |
```

（定时转账、AA 收款是独立 SOP，各自再填一份。）

## 三、为什么长这样：每个字段的设计依据

这个格式不是自创的，每个字段都有出处，且各自对应一条评分项或一个技术产物：

| 字段 | 设计依据 | 原始来源 |
|---|---|---|
| 整体「SOP 模板化」思路 | 蚂蚁开源的 agentUniverse 框架核心方法论：把金融业务中验证过的流程标准化为可复用模板（框架中叫 agent template / SOP 注入）。我们抄的是「流程即资产」这个思想 | [agentUniverse（蚂蚁开源）](https://github.com/antgroup/agentUniverse) · 调研文档 §2 |
| 步骤里的「自检 + 回执」 | 来自蚂蚁 PEER 模式的 Express（结果讲成人话）与 Review（执行后核对）环节；论文显示该模式在七维评测上显著优于无 Review 的基线。对应评分 40% 中的「多步骤任务规划合理性」 | [PEER 论文 arXiv 2407.06985](https://arxiv.org/abs/2407.06985) |
| 确认点 | 赛题评分 30% 安全合规**明文要求**「敏感操作确认和风险提示」；OWASP LLM Top 10 的 LLM06「过度代理」（模型不得自主执行敏感动作）与 OWASP Agentic Top 10 的 ASI02「工具滥用」都指向同一结论：动钱的动作必须人审 | [OWASP LLM Top 10 2025](https://genai.owasp.org/resource/owasp-top-10-for-llm-applications-2025/) · [OWASP Agentic Top 10 2026](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/) |
| 例外 | 评分 30% 交互体验点名「错误恢复、超范围兜底」；技术上每个例外将来就是流程图的一条分支——不写出来，系统遇到就只有崩溃或硬猜 | 赛题评分维度（[参赛规则离线副本](../../官方资料/参赛规则与提交要求.md)第四节） |
| 触发要「口语原话」 | 评分 30% 点名「口语化输入」。收集的真人说法后续直接复用为：①测试集的输入用例 ②演示视频的台词——一份劳动三处复用 | 同上 |
| 为什么只有五个字段 | 每个字段恰好对应一个技术产物，一一映射、零冗余：触发→意图路由；步骤→流程节点；例外→条件分支；确认点→人工确认门；回执→消息模板。填完即可直译成 LangGraph 流程图 | [LangGraph 文档](https://docs.langchain.com/oss/python/langgraph/persistence) · 调研文档 §1.1 |
