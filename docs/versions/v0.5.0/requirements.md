# v0.5.0 需求：联动、系统验收与体验打磨

> 阶段目标：完成跨场景联动（由 v0.4 移至，2026-10-11 项目负责人决定），用完整业务和安全评测证明核心系统可用，并修复影响演示和评分的问题。

## 背景

三个核心场景完成后，需要统一验证任务完成率、安全合规、恢复能力和适老化体验。

## 范围

- 完成跨场景联动公开能力和评测（v0.4 移至：先账单后联动；涉及资金的逐笔确认、部分成功与收尾）。
- 运行三场景任务评测和安全评测。
- 完成跨模块集成测试与缺陷修复。
- 核对审计证据、恢复、防重复和用户状态表达。
- 补齐契约已定义、尚未实现的管理端审计导出：F35 `POST /admin/audit/exports`（按固定筛选范围导出，返回 `ExportView(kind=audit)`）与 F24 的 audit 下载分支（核验独立管理权限 + 创建时固定的导出范围；数据源用既有 `audit/journal` 只读端）。来源 [Issue #121](https://github.com/DrErwin/hackerthon-bank-agent/issues/121)：2026-10-13 PM 决定**不进 v0.4、挂 v0.5**，实施票在本版本开工时按一票一目录拆（`backend/app/api/`），拆票前不改变本决定。
- 打磨关键演示路径和适老化交互。
- 形成核心能力验收记录。

## 验收标准

1. 三个核心场景的主要和关键异常路径通过。
2. 安全评测能够证明确认、权限、注入防御和隐私边界。
3. 演示环境可重置，结果可重复。
4. 已知限制和遗留问题有明确记录。

## 本版本不做

- 为提高展示数量而新增未验证场景。
- 真实银行和生产部署。
- 比赛材料最终提交动作。
