# v0.1.0 需求：PRD 与业务范围基线

> 阶段目标：确定首版银行 Agent 要解决哪些业务问题，并为各模块提供可评审的业务流程、边界和验收例。

## 背景

团队需要先统一转账、账单、跨场景联动、安全底座和模拟银行的职责，避免开发期间反复争论业务范围。

## 范围

- 完成转账、账单、跨场景联动三个业务 PRD。
- 完成安全底座与 Mock Bank 公共 PRD。
- 明确每个场景的公开能力、主要流程、关键异常和本期不做内容。
- 通过预审会收口跨模块业务选择和责任归属。

## 验收标准

1. 五份 PRD 均有明确状态、范围、流程和验收例。
2. 涉及资金的确认、安全和银行职责边界一致。
3. 待定问题有负责人和后续落点，不靠实现人员猜测。
4. PRD 可以作为下一阶段公共契约的输入。

## 本版本不做

- 公共 Pydantic 契约实现。
- 业务代码、前端和端到端运行验证。
- 真实银行或真实资金接入。
