> 阶段目标：在已验证的纵向框架上完成账单分析、完整安全能力和完整前端替换。跨场景联动按项目负责人 2026-10-11 决定移至 v0.5（先账单后联动）。本版本最晚 2026-10-20 收口（PM 硬截止，2026-10-11 决定）。

## 背景

普通转账先验证公共框架；后续业务应复用同一 Harness、契约、安全入口、银行接缝和审计能力，而不是另建运行体系。

## 范围

- 完成账单分析公开能力和评测。
- 补齐安全底座与安全评测集（包括 v0.3 遗留：真实风险检测器、#84 规划入口上下文、#85 确认/验证历史只读回放、安全评测完整性扩充）。
- 验证跨模块只调用公开能力，确认与验证记录按可信引用交接。
- 梁爽主责、六水协助实现完整前端，接入当期业务场景（转账、账单）并替换Erwin的简易联调前端；保持同一公共契约和运行日志。
- ~~跨场景联动公开能力和评测~~ → **移至 v0.5**（2026-10-11 项目负责人决定）。

## 验收标准

1. 账单场景复用 v0.3.0 公共框架。
2. 业务模块不直接访问其他模块私有工具或银行表。
3. 涉及资金的跨场景动作逐笔经过确认和安全检查。
4. 当期场景（转账、账单）的业务与安全评测达到各自 PRD 标准；联动在 v0.5 达标。
5. 完整前端替换后重跑确认、验证、刷新恢复、重复点击和真实结果展示；已验证的安全与资金闭环不能回退。

## 本版本不做

- 订阅、卡片、理财等候选扩展场景。
- 多 Agent 通用调度平台。
- 比赛提交材料的最终制作。
