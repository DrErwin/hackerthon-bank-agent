# v0.3.0 需求：普通转账纵向链路

> 阶段目标：用普通转账完成第一条可运行、可确认、可恢复、可回放的 Agent 纵向链路。

## 背景

需求和契约已经冻结，但框架仍未通过真实业务验证。本阶段以“给妈妈转 500 元”为信心锚点，证明总体架构能够运行。

## 本阶段执行安排

- Erwin 负责纵向后端主链路：底座、模拟银行、最小安全门和普通转账参考实现，并按目录拆成独立票和 PR。
- 梁爽主责、六水协助，本阶段只交一份普通转账关键流程原型图；不要求独立 UI/UX 规范、前端骨架或页面实现。
- Erwin 负责简易前端和真实接口联调，用于验证本阶段闭环；后续由梁爽、六水完成的完整前端替换，视觉与动效打磨保留到 v0.5.0。
- Ringo 负责安全评测并审查最小安全实现；转账评测与 14 步业务流程审查由 Erwin 承担（09-28 全员会定）。
- Erwin 负责模拟银行与端到端评测；周恩宇可以并行准备账单、跨场景评测，但不阻塞 v0.3.0。
- 这是 v0.3.0 的临时执行安排，不改变安全、转账等目录的长期归属。

各工作线可以在规格和契约冻结后独立拆票，不需要等待 Erwin 先拆完全部实施票。

分阶段排期、开始信号和状态更新方式见[实施计划](implementation-plan.md)。

## 范围

- 平台底座与模拟银行。
- 安全执行门与安全评测。
- 普通转账 14 步业务流程。
- 普通转账关键流程原型图，以及 Erwin 的简易联调前端；保持信息清楚、确认与验证入口独立。
- 纵向集成与里程碑验收。

详细业务范围和 AF01—AF14 验收见[场景规格](../../../.scratch/transfer-agent-framework/spec.md)；跨团队采用[五个交付包](../../../.scratch/transfer-agent-framework/packages/)。

## 验收标准

1. 自然语言请求能够进入普通转账公开能力。
2. 资金提交经过当前确认、有效验证、安全放行和模拟银行检查。
3. 页面刷新、服务重启、重复点击和提交超时不会造成重复转账。
4. 用户回执、任务状态和银行结果一致。
5. 完整运行链路可以按任务脱敏、只读回放。
6. 场景规格 AF01—AF14 全部通过。

## 本版本不做

- 定时转账和 AA 收款。
- 账单分析与跨场景联动实现。
- 多 Agent 调度、真实银行、真实短信或真实人脸。
- 大型观测平台、复杂视觉设计系统、完整前端实现与替换、前端动效打磨。
