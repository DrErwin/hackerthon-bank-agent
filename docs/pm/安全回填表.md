> 从哪来：[安全底座 PRD](../prd/安全底座父级-PRD-2026-09-23.md) 第 17 章的回填模板，拆成"**会前必填 / 会后补齐**"两半
> 交回给：Ringo（抄送 Erwin）
> 为什么填：Ringo 的安全底座是全系统的安全总章程，但他不知道你场景里的具体事实。这张表就是把事实抄给他——他能据此定安全规则、写测试用例；**安全分占 30%，没有这张表就没有验收口径**。

## 一、这张表分两次填

| 时间 | 填哪些 | 花多久 | 为什么是这个时间 |
|---|---|---|---|
| **预审会前一晚** | **会前部分（5 行）**：场景一句话、敏感操作、确认内容、关键内容、待确认问题 | 15—20 分钟 | 全是从自己 PRD 里**抄**的，不需要新决定；预审会讨论 X7（确认方式）/ X9（查账门槛）/ K7（身份验证）全靠这 5 行 |
| **预审会后 → 联评会前** | **会后部分（10 行）**：其余全部 | 半小时左右 | 分工和争议点开完会才清楚；有两行要引用联评决议（身份验证、撤销补偿） |

**一条铁规则：填不动的格子，写"待确认 + 卡在谁 + 为什么"，不要猜。**
"填不出来"本身就是预审会要收集的信息；空着或瞎填才是错的。

## 二、会前必填的 5 行

每行三个问题：这行问什么 → 去自己 PRD 哪里抄 → 抄成什么样。

| # | 行 | 这行问什么 | 去哪抄 | 提示 |
|---|---|---|---|---|
| ① | **场景与完整任务** | 你的场景里，用户从头到尾办成一件什么事（一句话） | PRD 的"产品目标 / 一句话目标" | 一句话就够，这是表头 |
| ② | **敏感操作** | 哪些步骤会**动钱 / 改权限 / 把敏感数据交出去 / 产生外部影响** | PRD 的"确认点 / 安全与确认考虑" | **不止动钱才算**：02 读取消费明细、导出报告，06 把收货地址交给外部服务，都算。对着安全底座 §10.1 的清单过一遍 |
| ③ | **确认内容** | 每个敏感操作执行前，用户**必须看到**哪些信息 | PRD 的确认单 / 确认点清单 | 01 的确认单 8 项直接抄过来 |
| ④ | **关键内容** | 哪些信息**一变，刚才的确认就作废**、必须重新确认 | PRD 里"关键字段变化 / 确认失效" | 通常就 3—5 样：收款人、金额、账户、时间 |
| ⑤ | **待确认问题** | 填上面三行时卡住的问题 | 现场产生 | 写法：问题 + 卡在谁 + 影响哪一步 |

## 三、会后补齐的 10 行

开完预审会再填。有两行要引用联评会的决议，没决议前标"待确认"。

| # | 行 | 这行问什么 | 提示 |
|---|---|---|---|
| ⑥ | 涉及的用户和第三方 | 谁发起，谁的数据或权益会被影响（收款人、外部商家都算） | — |
| ⑦ | 读取的数据 | 读什么、从哪读、用来干嘛、给用户看多大范围 | — |
| ⑧ | 修改的数据或外部影响 | 改了什么、什么时候生效、影响是什么 | — |
| ⑨ | 身份验证需求 | 哪些操作要先验身份 | **引用 K7 的决议**；没定就标待确认 |
| ⑩ | 可能的越权路径 | 用户或 AI 可能"碰到不该碰的东西"的路径（查别人账、用别人的账户） | 对着安全底座 §9 四类威胁里的"越权操作"想 |
| ⑪ | 可能的注入来源 | 哪些**外部文字**可能夹带指令（账单备注、商家名、网页、工具返回） | 对着 §9 的"Prompt 注入"想；02 尤其注意商户名 |
| ⑫ | 修改与取消 | 什么阶段能改 / 能撤，提交以后怎么跟用户说 | **引用 D11 决议**（银行不提供撤销） |
| ⑬ | 失败与结果未知 | 失败怎么告知；结果未知时先查原操作、不重发 | 对着 Mock Bank D09 / D09-b 的超时口径写 |
| ⑭ | 撤销与补偿能力 | 已支持 / 暂不支持 / 待确认 | **引用 D11 决议**；没定就标待确认 |
| ⑮ | 反向验收例子 | 至少 2 个"**绝对不能发生**"的结果 | 直接从自己 PRD 的验收表里挑最狠的两条 |

## 五、填好的样子（节选自 01 普通转账，照这个颗粒度抄）

**会前部分：**

| 项目 | 内容 |
|---|---|
| 场景与完整任务 | 普通转账：用户说"给妈妈转 500"，系统找对人、算好钱，用户确认后转出，返回真实结果 |
| 敏感操作 | ① 提交转账（唯一动钱动作）② 查询收款人候选、查询余额（敏感读取，不改数据） |
| 确认内容 | 确认单 8 项：转出账户名及尾号 / 收款人姓名或备注 / 收款开户行及尾号 / 金额 / 执行时间 / 到账方式及预计到账 / 手续费（无则 ¥0.00）/ 风险提示或核验状态 |
| 关键内容 | 收款人、金额、转出账户、执行时间——任一变化，原确认失效 |
| 待确认问题 | 到账方式选择是否进 P0（卡 D03 / D15，找梁爽+Erwin）；模拟身份验证谁提供（K7，会前定） |

**只读场景怎么写（给六水的参照）**：02 不动钱，敏感操作照样有——"查询本人消费明细""生成并导出账单报告"都是敏感读取/导出；确认内容那行写"导出或转发前须用户确认"；待确认问题里正好挂 X9（查账要不要先验身份）。
