## 五个模块的关系

| 模块 | 在系统中的角色 |
|---|---|
| LangGraph 框架 | 提供运行状态、分支、暂停和恢复能力 |
| 内层 Harness | 基于 LangGraph 构建，采用 Deep Agents 组织任务和工具调用 |
| 安全基座 | 对操作执行统一授权、校验和敏感确认；也为入口和数据访问提供共同策略 |
| 模拟银行 | 执行模拟银行业务并返回可核实结果；入口再次校验关键条件 |
| 前端用户交互 | 用户发起需求、查看进度、提交确认和接收结果 |

主调用关系：前端 ↔ Harness → 安全基座 → 模拟银行。Harness 向下依托 LangGraph，属于构建与运行承载关系，不是两个独立 Agent，也不是两级审批。

前端与 Harness 之间经过 API；请求使用 HTTP，进度使用 SSE。需要用户确认时，Harness 借助 LangGraph 暂停任务，前端提交确认后再继续原任务。安全拒绝或等待确认时不执行银行操作；银行实际结果沿调用链回到 Harness，再展示给用户。

图中五个框是评审所需的大模块，不表示五个独立服务。内部工具、业务模块和存储不再单独展开；原 [详细模块清单](system-modules.md) 留作补充材料，不作为当前主图的拆分层级。
