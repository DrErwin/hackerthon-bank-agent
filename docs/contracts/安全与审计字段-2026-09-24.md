# 公共契约附件：安全裁决与审计字段

> 最后更新：2026-09-27（文件名沿用创建日期）

> 状态：**v1 已冻结（2026-09-27，Erwin 确认）**；业务口径与必要安全补充已收口，可按此并行开发。未实现、未通过测试；不代 Ringo 签核实现安全。

## 1. 类型、身份与执行边界

通用 ID、Money、Timestamp、BankError 引用[银行字段附件](银行接口字段-2026-09-24.md)。无 `?` 的输入必填；输出字段全部存在，可空用 null。ID 是关联标识，不是授权凭证。所有时间戳区分实际时间和银行模拟业务时间。

| 类型 | 代码值 | 含义 |
|---|---|---|
| OperationLevel | read / modify / sensitive | 一级读取 / 二级修改 / 三级敏感 |
| RiskLevel | low / medium / high | 低 / 中 / 高，与操作等级独立 |
| SecurityDecisionCode | allow / require_input / require_confirmation / require_verification / block / pause | 六种已定裁决，不增加新裁决 |
| Phase | admission / execution / recovery | 请求准入 / 每次实际动作 / 中断恢复 |

`ExecutionSecurityContext` 由服务端构造：`user_id:ID`、`session_id:ID`、`demo_round_id:ID`、`task_id:ID`、`run_id:ID`、`source_task_id:ID|null`、`operation_id:UUID|null`、`action_revision:int|null`、`confirmation_id:ID|null`、`confirmation_version:int|null`、`verification_ids:ID[]`、`release_authorization_id:ID|null`。最后一项仅供 §3.1 的确定性释放收尾，普通业务为空，不由模型填写。查询无写操作编号可空；每个副作用动作在提交前持久化其独立编号。任务关系来自平台记录，不能由调用方自报父任务取得授权。

`ActionDescriptor`：`action_name:string`、`parameters_ref:ID`、`resource_refs:ID[]`、`phase:Phase`。参数引用指向当前版本受控快照，副作用、权限要求、操作等级从已登记工具读取，不接受模型覆盖。`security.check_action(context, action) → SecurityDecision` 是公共逻辑入口；准入通过不替代执行时再检查，业务私有工具同样经过该入口。银行收到自己的可信身份与操作信息，不要求银行理解 LangGraph 检查点。

## 2. 安全裁决结构与状态映射

| 字段 | 类型 | 必填与规则 |
|---|---|---|
| decision_id / task_id / run_id | ID | 全部必填，后端生成或可信关联 |
| action_name / parameters_ref | string / ID | 绑定本次动作和实际受控参数 |
| operation_id / action_revision | UUID 或 null / 正整数或 null | 写动作必有；尚在意图澄清的准入检查允许空 |
| phase / operation_level | Phase / OperationLevel | 工具登记与调用阶段决定 |
| risk_level | RiskLevel 或 null | 没有足够证据时允许空，但此时不得 allow |
| decision | SecurityDecisionCode | 六种之一 |
| reason_codes | string[] | 稳定的策略原因编号；非 allow 至少一项 |
| rule_ids / policy_version | string[] / string | 命中规则与规则版本，不用自然语言替代程序分支 |
| authorization_snapshot_ref | ID 或 null | allow 执行敏感动作时必填，指向下述不可覆盖的脱敏授权快照；尚无授权时为空 |
| evidence_refs | ID[] | 受控事实引用，模型判断依据与确定性检查事实区分留痕 |
| interaction | 主契约 InteractionRequest 或 null | require_* 对应 input / confirmation / verification，其他为空 |
| checked_at | Timestamp | 实际检查时间 |
| message | string | 脱敏用户说明，不输出秘密或完整内部策略细节 |

| decision | 动作与任务处理 | 可提供的后续动作 |
|---|---|---|
| allow | 仅允许当前匹配动作进入执行器，仍接受银行最终检查；不代表业务已成功 | 由业务当前状态决定 |
| require_input | waiting_input，不提交动作 | provide_input、cancel |
| require_confirmation | waiting_approval，引用当前确认单 | confirm、cancel |
| require_verification | waiting_approval，引用当前验证 | verify、cancel |
| block | 当前动作不执行；高风险或终止规则结束原任务，不提供恢复放行 | 可查询已发生动作结果；不能 resume 被终止任务；已有冻结仅可按 §3.1 限定授权收尾 |
| pause | needs_attention；查询或故障恢复之前不继续执行 | 按原因提供 query / resume / cancel，不提供重做未知写动作 |

单任务无已完成动作而被终止时为 failed；已有成功子动作时保留每项事实，复合任务为 partially_succeeded；仍有未核实动作时为 needs_attention，保留“禁止继续购买／转账”的终止标记（§3.1 限定释放收尾除外），后续查清也不恢复购买／转账；需要释放未消费冻结款时仅按 §3.1 处理。用户明确取消与安全阻断分别留痕；不得把 block 伪装成用户 cancelled。

检查先核验可信身份与资源归属，再评估输入完整性及风险；明确越权 / 高风险直接 block，不能让用户补一次确认便绕过；需要确认和验证时按已定顺序逐步获取。allow 不是可传递令牌，恢复、参数变化或新动作必须重新检查。

F10 / F11 / F15 / F17 / F18 / F20 及跨模块入口在推进动作前统一检查后端终止标记；不能因任务显示 partially_succeeded / needs_attention 就恢复购买或转账。前端 allowed_actions 不提供复活这些动作的入口；已发生动作可查询核对，§3.1 的确定性限定释放仍可收尾。新任务不得复用旧任务的动作确认或中风险验证；低风险基础验证仍按有效会话范围复用。

执行前核对本次裁决与实际用户、会话、轮次、任务、操作编号、动作版本及参数一致；状态或风险事实改变时重新裁决。限定释放按 §3.1 的受控收尾身份和授权记录核验，不要求原会话仍有效。source_task_id 来自平台实际调用链，并与父子关系、委派能力和资源范围匹配；无权引用直接拒绝，不以补确认换取权限。具体执行凭据沿现有可信上下文实现，不在本轮强制新增 execution_authorization_ref。

原因代码最小集合：`AUTH_REQUIRED / ACCESS_DENIED / INPUT_REQUIRED / CONFIRMATION_REQUIRED / CONFIRMATION_EXPIRED / CONFIRMATION_STALE / VERIFICATION_REQUIRED / VERIFICATION_SCOPE_MISMATCH / VERIFICATION_FAILED / VERIFICATION_TIMEOUT / HIGH_RISK / POLICY_VIOLATION / OPERATION_UNKNOWN / DEPENDENCY_UNAVAILABLE / AUDIT_UNAVAILABLE / STALE_ROUND`。风险触发条件沿用安全 PRD 与 01 §9.2，Ringo 负责将检测规则版本化；判据不能由业务模型自由填写。银行原因由 BankError 表达，不在安全侧复制余额 / 限额规则。

## 3. 确认与验证记录

确认、验证核心字段见[确认验证字段表](确认验证字段-2026-09-24.md)，本节补全与前端交接约束。

`DisplayField`：`name:string / label:string / value_text:string`；全部已脱敏。金额同时以元展示，原整数分在受控参数快照中；前端 answer 不携带替换参数。`VerificationChallenge` 中增加 `demo_round_id:ID`，且明确 `code_created_at:Timestamp`、`face_started_at:Timestamp|null`、`face_expires_at:Timestamp|null`。面部模拟未开始时截止为空，第一次 F20 才开始其 5 分钟期限；重复 F20 不续期。中风险尚未通过的验证码按其实际截止时间判断，不能借晚启动人脸避开已发生的验证码超时；已在期限内通过的方法不因作答期限随后到达而失效，成功记录按会话 / 动作范围判断。

challenge_status 增加 cancelled 以表达用户取消；code_result / face_result 使用 pending / passed / failed / expired / cancelled，face 额外允许 not_required。第一项真实失败或超时即按中风险终止，不等待另一项。低风险码过期可重发，failed 仅表示本次错误事实，未满三次时可继续；三次终止记录由安全任务状态控制，不因新 challenge 清零。

为避免“重发验证码重置人脸”的歧义，`bank.resend_verification_code` 创建替代 challenge 时继承同一动作、真实已取得的人脸结果及人脸原始期限，中风险同时继承原 code_expires_at（即使到期前重发也不延期），验证码结果重新置 pending、旧验证码失效、错误次数不归零；不得继承不同动作 / 会话 / 轮次的结果。任务已终止或挑战整体已通过时不通过重发改写原结果。验证码专用输入、HTTP access log 与异常追踪均不得记录秘密原文，去重只保存必要结果，比较重复请求时使用受保护的不可还原比较值而非持久化验证码请求体。

### 3.1 冻结款的限定释放授权（09-26 Erwin 已确认）

`FreezeReleaseAuthorization` 为后端受控记录：`release_authorization_id:ID`、`user_id / session_id / demo_round_id / task_id:ID`、`account_id:ID`、`freeze_operation_id:UUID`、`freeze_id:ID|null`、`confirmation_id:ID`、`confirmation_version:正整数`、`max_amount_fen:Money`、`granted_at:Timestamp`、`status:pending_freeze|active|completed|invalid`。session_id 记录最初授权来源，不是之后的一般执行凭证；max_amount_fen 为原确认冻结金额，实际只能释放银行已核实未消费余额。冻结成功后绑定 freeze_id 并 active，明确冻结失败则 invalid，未知先回查。确认作答前不得生成已生效授权。

限定授权只覆盖同用户、同任务、同轮次、同原账户的该笔冻结结束收尾，不能转给别的账户或扩大到扣款、下单、退款。取消或安全终止不撤销它；原确认的一小时是接受冻结确认的时限，不使已取得的结束释放授权到点消失。登录过期后由后端受控收尾身份持该限定记录执行，不借旧 session_id 通过普通业务授权；银行仍校验可信主体对原冻结的释放权限。清空本轮后旧授权失效。

执行器只对 `bank.release_frozen` 的收尾核对有效限定记录、已停止购买、在途已核实和当前未消费余额；该路径不再次等待用户确认／验证，不复活终止任务，不允许模型发起或扩大授权。必要日志失败先暂停；释放未知只查原 operation_id。原业务结果保留，收尾未完成为 needs_attention 且禁止继续购买，剩余额为零后记 completed。规则不改变一般动作的会话、确认、验证要求。

收尾的 security.decided、tool.started / finished、bank.observed 在既有事件中追加 `release_authorization_id:ID` 和 `freeze_id:ID`；授权内容随原冻结 confirmation.changed 的 display_ref 脱敏保存，执行快照关联结束原因。记录实际系统操作者和目标用户，不能冒记用户再次点击确认。

验收见 S07，与主契约 M14 对应。

## 4. 审计事件公共外壳

使用追加事件，同一 run 内 sequence 严格递增；跨调用用 trace/span 父子关系关联，不假定分布式真实时间能建立唯一总顺序。payload 按 event_type 校验，不能任意丢字段；大文本可由内容快照引用表达。

| 字段 | 类型 | 条件 |
|---|---|---|
| event_id / trace_id / span_id | ID | 必填；event_id 用于去重 |
| sequence | 非负整数 | 同一 run 内事件序号；无 run 的管理 / 访问事件在自身 trace 内排序 |
| parent_span_id | ID 或 null | 顶层为空，子调用填写实际父调用 |
| demo_round_id / actor_id | ID | 演示轮次及实际操作者；系统触发使用明确的系统身份 |
| session_id | ID 或 null | 实际操作者的登录会话；用户及管理员发起必填，纯系统触发为 null，不把原授权会话当作系统当前登录 |
| target_session_id | ID 或 null | 操作明确针对某会话时必填，例如使会话过期；其他为空，与操作者会话分别记录 |
| target_user_id | ID 或 null | 有目标用户时必填，不能借此授权读取 |
| thread_id / task_id / run_id | ID 或 null | 业务事件按实际关联必填；纯管理、审计查看可空 |
| module / event_type | string / 下表事件类型 | 来源组件与分类 |
| timestamp / logical_at | Timestamp / Timestamp 或 null | 真实时间；涉及银行模拟业务时间必填 logical_at |
| outcome | started / succeeded / failed / waiting / unknown / denied | 事件结果，不替代银行或任务状态 |
| evidence_ref / evidence_status | ID 或 null / available 或 missing 或 restricted | 有内容快照则引用；缺失显式记录 |
| missing_reason | string 或 null | missing / restricted 时必填，不能用事后模型推断填空 |
| payload | 下表对应结构 | 所列字段必有；可空处明确标记 |

内容快照 `EvidenceSnapshot`：`evidence_id / media_type / content_ref / redaction_version / content_hash / created_at`；content_ref 指向可读取的受控脱敏内容，不是任意路径 / URL。hash 仅作一致性校验，不声称不可篡改证明。管理查看和导出重新鉴权；用户界面不提供任意 evidence_ref 读取入口。

每次解析证据引用均检查当前管理权限、获准的历史或当前轮次及审计范围；持有编号不等于有权读取。导出只读取本次授权范围内的脱敏证据，缺失或失效引用明确标记，不回退读取未脱敏原文。

`AuthorizationSnapshot` 作为 EvidenceSnapshot 的受控脱敏内容保存：`user_id / session_id / demo_round_id / task_id:ID`、`operation_id:UUID`、`action_revision:正整数`、`confirmation:{confirmation_id:ID,version:正整数,decision:string,decided_at:Timestamp,display_fields:DisplayField[]}|null`、`verifications:{verification_id:ID,scope:session|action,methods:string[],verified_at:Timestamp,operation_id:UUID|null,action_revision:正整数|null}[]`、`release_authorization_id:ID|null`、`captured_at:Timestamp`。这里的 session_id 是取得授权的来源会话，与事件外壳实际操作者会话区分。一般敏感动作 confirmation 必有；限定释放引用原冻结确认与限定授权，不伪造新用户确认；不需要验证时 verifications 为空。仅保存发生时的事实，不含凭据、验证码或可执行令牌，不能用快照再次授权。

在敏感执行 allow / tool.started 前持久化快照，失败按原审计失败规则暂停；security.decided 通过 authorization_snapshot_ref 引用，tool.started 的 decision_id 连接同一裁决。历史授权证据与临时任务材料分开保存，演示重置或会话失效不能让原证据变成悬空引用；重置后回放仍显示原轮次、操作者会话及目标会话，禁止用当前记录覆盖历史事实。

## 5. 审计分类字段（所有列出字段必填）

表中 `?null` 表示字段存在但值可空。RequestRef / ResponseRef 等均是 EvidenceSnapshot 的 ID；秘密在生成快照前移除。开始与结果事件通过同一个调用编号关联，缺结果事件显式显示缺口。

| event_type | payload 字段 | 用途 |
|---|---|---|
| chat.message | message_id:ID、role:user/assistant、content_ref:ID、related_task_ids:ID[] | 保留用户输入和最终助手回复；无逐 token 日志要求 |
| model.started | model_call_id:ID、provider:string、model:string、config_version:string、request_ref:ID | 实际输入提示、上下文、生成参数在脱敏 request 快照中，不能只留模板名 |
| model.finished | model_call_id:ID、response_ref:ID?null、duration_ms:非负整数、usage:{input_tokens:int?null,output_tokens:int?null}、error:ModuleError?null | 模型实际输出、明确提出的计划与工具调用；用量不可用为 null，不编 0 |
| context.changed | change:memory_load/compression/resource_load、before_ref:ID?null、after_ref:ID、source_refs:ID[] | 实际进入上下文的内容；压缩前后可追溯 |
| task.transition | previous_status:TaskStatus?null、status:TaskStatus、plan_revision:int?null、step_id:ID?null、reason_code:string、checkpoint_ref:ID?null | 状态与计划步骤变化；检查点仅为内部关联，不暴露执行入口 |
| tool.started | tool_call_id:ID、tool_name:string、tool_version:string、arguments_ref:ID、decision_id:ID、operation_id:UUID?null | 全部公开和私有工具；副作用动作 operation_id 必填 |
| tool.finished | tool_call_id:ID、operation_id:UUID?null、result_ref:ID?null、duration_ms:int、error:ModuleError?null | 实际结果或失败，未知如实标记；银行回执保存在 result 快照 |
| security.decided | decision:SecurityDecision | 完整的后端裁决，不使用模型自报批准 |
| confirmation.changed | confirmation_id:ID、confirmation_version:int、action_revision:int、decision:string、display_ref:ID、operation_id:UUID?null | 展示 / 批准 / 取消 / 过期 / 内容失效各次记录，绑定确认内容 |
| verification.changed | challenge_id:ID、method:code/mock_face、result:string、purpose:string、operation_id:UUID?null、verification_id:ID?null、consecutive_code_failures:int、expires_at:Timestamp、reason_code:string | 不保存验证码、人脸原文或可还原秘密；技术故障与输错分开 |
| bank.observed | operation_id:UUID、lookup:found/not_found/error、operation_status:succeeded/failed/processing?null、transaction_id:ID?null、receipt_ref:ID?null、error:BankError?null | 初次银行回执和原操作回查；not_found/error 不伪造原操作失败 |
| recovery.checked | previous_run_id:ID、current_run_id:ID、checkpoint_ref:ID?null、operation_ids:UUID[]、result:continue/wait/stop、reason_code:string | 恢复决定及被核对动作，不能从日志直接恢复执行 |
| admin.changed | management_operation_id:ID、action:string、target_ref:ID?null、source_round_id:ID、resulting_round_id:ID?null、before_ref:ID?null、after_ref:ID?null、error:ModuleError?null | 开关、人脸模拟、过期、快进、重置的实际操作者和结果 |
| audit.accessed | action:list/read/export/download、filter_ref:ID?null、target_refs:ID[]、export_id:ID?null、permitted:bool、reason_code:string | 日志查看本身留痕，不递归触发新的查看事件 |

凡事件指向对话、参数、回复或工具数据，均遵守主契约脱敏规则。已有安全事件不能覆盖或删除；核对后追加修正说明与原 event_id 的引用，保持原始历史可见。没有日志不等于业务未执行。

## 6. 错误码归一与验收

HTTP 外壳使用主契约 ModuleError，银行 BankError 放入 upstream_code 与受控事实；403 不透露他人记录存在，404 仅用于已获准范围内确实不存在。旧轮次 STALE_ROUND、确认旧版本 / 已失效、操作记录冲突和任务终止后作答均为 409；认证故障 401，访问拒绝 403，依赖故障 503。真实验证失败作为核验事实返回，不能当成 HTTP 503；用户输错不得被服务错误增加次数。

确认 / 验证错误沿用字段表；追加 `TASK_TERMINATED / CHALLENGE_EXPIRED / CHALLENGE_SUPERSEDED / EXPORT_NOT_READY / REQUEST_CONFLICT / MANAGEMENT_CONFLICT` 的 409 映射。未注册工具及未声明权限直接拒绝，不隐式降级为只读工具。具体用户话术不作为程序分支依据。

| 验收编号 | 需要证明的行为 |
