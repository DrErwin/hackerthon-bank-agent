## 五、并行开发工作流（全员从此按此流程干活）

1. **交付包**：每个阶段（0.3、0.4…）按工作线拆成交付包（底座 / 前端 / 转账 / 安全…）放到 GitHub；各自把自己的交付包拆成一张张票据（ticket）。
2. **三个主 skill**（Matt Pocock 套件，Erwin 会后发给大家装）：
   - **to-spec**：把交付包变成规格说明书（specification）；
   - **to-tickets**：把 spec 拆成一张张可勾选、可追踪、带依赖关系的票据（"一做完才能做二"）；
   - **implement**：逐票执行；AI 会自动挑最近可做的票。**每做一个任务新开一个对话窗口**，一个阶段尽量在一个窗口内完成。
3. **辅助 skill**：**grill-me**——AI 反问你、给选项和推荐，把交付包的细节全部对清楚（会上用 GLM 现场演示过效果）；**ask-matt**——流程中任何不懂直接调它问。
4. **分支与合并**：各线在各自分支推进（如 A 线 a1→a2、B 线 b1、C 线 c1→c2），做完提 PR，Erwin 按链路状态挨个合入；冲突不用担心，并行开发原则已写进 AGENTS.md，AI 会读并处理。
5. **会后动作**：所有人把 **GitHub 账号 + 邮箱**发给 Erwin 拉进仓库；梁爽进飞书 team；Erwin 另写一份**给人看的** AI 使用注意事项文档（现有文档多为给 AI 看的），内容是他自己的使用经验。
