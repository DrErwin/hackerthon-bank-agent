## 二、协作流程

### 沟通节奏

- **例会**：一周至少一次，倾向周二 / 周四，提前协调（不固定日期）
- **日常**：随时在群里说，卡点第一时间发出来
- **三种求助途径**：问 AI → 群里问 → 私聊 Erwin
- **例会形式**：每人讲这几天的推进、卡点、下一步，不用做 PPT

### 需求与文档流程

各模块 PRD 定稿（09-21）→ 需求评审会（09-22）→ 契约与总体架构定稿（Erwin + Ringo，09-23~24）→ 全员定稿会（09-25/26）→ 分工开发。

跨团队纵向场景按[跨团队纵向交付与版本进度原则](principles/04-cross-team-delivery.md)推进：场景负责人先定规格和工作线交付包，正式任务表宣布后，各目录负责人再拆自己的实施票。`.scratch/` 文件不会自动通知或指派负责人。阶段完成后先更新对应版本的 `completion.md`，再启动下一版本。

**队员开工流程**：说明身份 → 定位本人正式交付包 → 明确接受 → AI 自动记录领取 → 检查并安装缺失的通用 Skill → `to-spec → to-tickets → 按票执行`。细则、记录字段与 Skill 来源见[队员开工规范](agents/delivery-workflow.md)；只咨询下一步不代表已经领取。

### 代码协作（开发阶段启用）

- **开分支前先读 `docs/principles/` 四份**：业务并行 / 安全底座 / Review 与合并 / 跨团队纵向交付
- 仓库为唯一代码事实源；`main` 分支保持可运行
- 个人在 feature 分支开发，通过 PR 合并，Erwin 审核
- 提交信息写清「做了什么 + 为什么」；**禁止提交真实密钥或敏感信息**
- 纯文档改动按 [AGENTS.md](../AGENTS.md) 的约定直接提交 main，不建 PR、不跑 CI
